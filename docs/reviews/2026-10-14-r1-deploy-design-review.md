## Bounded asynchronous native design

Planned invocation uses systemd-run **--no-block**, unique R1 deployment unit, Type=oneshot, Start3600, Stop1500, UMask0027, the concrete new scope as working directory, then definition pin → deployment helper with exact source/qualified receipt/pin/build/scope arguments. Concrete paths and receipt digest are still templates and must be frozen/read back before launch.

Start3600 bounds the entire oneshot phase, without promising completion for every worst-case command duration. On TERM the helper converts interruption into its exception path and ignores repeated TERM during cleanup. Individual command settlement is approximately bounded by10s communicate plus up-to20s metadata checks. Stop1500 accommodates bounded group cleanup, rollback canonical verify330, timer restoration and short handoff-state commands with the current120s defaults. Native final KILL remains finite; no design can claim successful restoration when a command/filesystem cannot settle. There is no ExecStopPost because the helper owns the stopped transaction cleanup; unresolved settlement deliberately produces failure rather than racing an additional restorer.

The deployment design does not repeat the cloud launcher's blocking-call mistake. Parent reports that the earlier cloud control caller timed out after native launch while the cloud itself remained healthy; it is not a source/test failure and must not be retried.
