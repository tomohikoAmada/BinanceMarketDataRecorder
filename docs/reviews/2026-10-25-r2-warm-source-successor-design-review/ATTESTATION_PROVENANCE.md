# Conditional static attestation boundary

A reusable receipt must bind the new scope/native capture, original warm begin/deadline, first strict raw SHA, real canonical argv/returncode/full original stdout+stderr/parse status, source20e57/wheel/config/identity/unit/profile hashes, expected boot, Recorder invocation/PID/NRestarts/service-instance and its actual UTC/BOOTTIME/monotonic interval. It must have been published/fsynced before reuse; its own SHA is an input, not a self-reported boolean. The default source full evaluator must be proven from the frozen canonical command and module origin/byte bindings; custom callbacks are forbidden in that first command.

Full READY must include real earlier installed_artifact/dependency/control-chain evidence and service identity/runtime matching this same warm. A bare `state:READY`, missing/partial evidence, wrong-source fixture, a previous stage/run/boot, or a forged `catalog_ok:true` cannot authorize reuse. The source full result does not separately emit an opened Catalog descriptor receipt: successful frozen default source control flow implies its default integrity check passed. Declare that inference, and retain canonical Catalog path plus symlink-free regular-file stat identity before/after the full command. Do not claim an atomic descriptor/ABA proof that was not collected.

The guarded catalog callback requires the exact current canonical path and the same device/inode/type/owner/permission identity, same boot/incarnation/config/identity and valid receipt/deadline. Missing/replaced/symlinked/unexpected paths or guards invalidate it. Ordinary database/WAL size/mtime changes from ongoing legitimate writes may be recorded and allowed; forbidding all growth would be incorrect. Consequently the receipt proves earlier metadata integrity, not fresh integrity of every later transaction. Current catalog-open/startup-recovery and all source runtime/product/capacity guards remain live, and eventual complete new-data audit is still required.

The guarded identity adapter redoes cheap source file hashes/path/permissions, live namespace control and current systemd checks. It reuses only the earlier installed RECORD/dependency contents. The frozen root-controlled release and no-authorized-redeployment contract is an explicit assumption over this short same-warm interval. It does not detect every hypothetical root mutation of an arbitrary dependency without a new full content scan. Any observed namespace/identity/decision-module change invalidates reuse. If the contract instead demands a fresh complete installed forest and Catalog integrity proof at T0, this design cannot honestly supply it while also forbidding a second heavy scan; it must not be mislabeled equivalent to stock full readiness.

There is no reusable cross-run lease. Expiry is the original1200s warm deadline, not first-command finish+1200. Clock regressions, boot changes, UTC/BOOTTIME/monotonic disagreement beyond the existing clock-trust allowance, restart/incarnation/PID mismatch or service-instance change invalidate it. These observations establish the expected service identity under the existing controlled systemd contract; counters/timestamps alone are not advertised as a universal lineage proof.

All source dynamic predicates are freshly evaluated through the real unchanged evaluator and providers. A conditional READY receipt names both reused static validators, their times/SHA/guards and the current source result. No unconditional True callback, cached process environment/PID liveness/service state or unconditional current capacity success is acceptable.

Success without durable attestation/completion evidence cannot reach T0. On a primary failure retain its original exception/reasons and all available raw bytes/timing; a later diagnostic-write failure is secondary and must not replace it. On an otherwise successful result, evidence-write failure is fatal to eligibility. Root controller remains the only service-control/automatic restoration owner; the read-only child never restores or retries a mutation. The already failed P3 data and CLOSED194e are never changed, extended or reused.
