## Smallest safe algorithm

1. Keep every other five-minute feed dense and unchanged. OI alone accepts valid bounded HTTP200 arrays with omitted periods, including empty arrays. Retain exact received SDK-model/provenance payload, request parameters and actual row endtimestamps. Do not round timestamps, relabel them as window starts, manufacture rows, require positive OI value, or claim exact HTTP wire bytes from the existing parsed-model SDK path.
2. Keep current closed **request time windows**: request_start is grid-aligned; inclusive request_end ends at the last millisecond of a fully elapsed five-minute bin. These bins partition the record-end timestamp domain. They are evaluation windows, not invented record timestamps. OI response validation retains symbol, required fields, integer timestamp and exact range bounds, while removing OI-only exact-start and dense+300000 requirements. A later/out-of-range row still cannot satisfy this request.

Retain the response and explicit incomplete-range evidence first, then refuse cursor/success advancement. The minimal practical recovery is one sticky integer ceiling per poller, halved on saturation through the existing retry path, with no extra queue/daemon/table or recursive unbounded requests. At one-window saturation fail closed; do not guess an offset or skip unread results. The unchanged per-attempt request cap remains in force.

Any Raw/event/cursor failure leaves success ungranted and permits safe duplicate re-evaluation after restart. No record is invented and no within-retention source-expected omission is mislabeled unrecoverable.
5. Reuse the existing cursor integer but give OI an explicit new meaning: **milliseconds of the start of the last fully evaluated closed request window**, derived solely from declared request bounds. For inclusive aligned end `e`, the value is `e-(P-1)`, equivalently `(((e+1)//P)-1)*P`, P=300000. A bare period ordinal must not be stored. Actual first/lastRequestedTimestamp stay real source endtimestamps in separate fields; they are never replaced by evaluation progress.

## Necessary legacy/restart boundary

The old cursor was a last returned row from an API response capped at the number of requested periods. It is not proof the remainder of that same time bin was read. Therefore an unconditional first start=old_cursor+P would silently skip an unproven part when changing semantics.

The minimal conservative solution is one per-poller boolean reset on construction/restart: if a stored OI cursor exists, first re-evaluate its own bin from floor(cursor/P)*P, including the previous boundary. After a full durable complete-range sequence, set the boolean and subsequently use evaluated_cursor+P. On a failed or saturated attempt keep it unset. Repeating this one bin after process restart is safe; its original and new observed requests remain honestly distinguishable by Raw connection/provenance. No old Raw audit, new table, persistent migration framework or scan of all historical range receipts is necessary. The fresh no-cursor bootstrap retains published retention bounds and honest outside-retention evidence, with sparse omissions kept distinct.
