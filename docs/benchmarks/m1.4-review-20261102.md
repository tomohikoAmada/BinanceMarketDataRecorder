# M1.4 独立复核与落地记录（2026-11-02）

## 结论与范围

任务 M1.4 聚焦于“热路径防御性拷贝移除”与“合并 REST 持久化线程交接”。本阶段全部工作在 Python 3.12 下完成，未引入跨语言重写，未破坏 Raw v1（ADR-0010）二进制磁盘字节格式与既有回放/归一化兼容性。

全部修改与优化已落地并完成验证，主要交付成果包括：
1. **热路径防御包装与冗余拷贝彻底移除**：删除 `spool/writer.py` 中的 `_ImmutableEnvelopeSnapshot` 及 `MappingProxyType` 防御包装，`RawChunkWriter` 直接基于 `EventEnvelope` 编码 CBOR 并累加统计；优化 `EventEnvelope.canonical_mapping()` 字典构造路径，获得约 3.7x 吞吐加速，且 CBOR 编码产物与原实现保持 100% 字节级一致。
2. **消除 REST 二次 JSON 解析**：
   - `capture_public_response()` 直接支持前置传入 `evaluated_period` 参数，在构造单份 REST provenance 时一次性序列化，彻底消除 `D16` 路径上的二次 `json.loads` 与 `json.dumps`；
   - `RestObservation`（及别名 `RestCaptureResult`）直接保留 `response_headers` 映射，使 `_observe_rest_rejection()` 无需解析 `raw_payload` 即可直接读取 `Retry-After`，消除 418/429 路径上的二次 JSON 解析。
3. **合并与批量化 REST 写盘线程切换**：
   - 保持 418/429 冷却门在进入存储等待前在事件循环中**同步生效**，确保不出现并发突发请求击穿冷却门的风险（通过 `test_p2_cooldown.py` 严格验证）；
   - 在 `persist_rest()` 中引入基于事件循环的协同合并机制：同属一个 `rest_observations` 分片的并发请求在内存入队后，合并由单次 `run_owned_blocking_call(spool.drain_all)` 批量刷盘，大幅降低线程池上下文切换开销。
4. **澄清并解决 WS 逻辑流名称与 Raw 分片格式契约**：
   - 原计划建议在 `envelope_for_group()` 中直接填入逻辑流名称以省去 `logical_envelope()` 的 `.model_copy()`。经核实，ADR-0010 及 ADR-0054 规定 WebSocket 物理分片按 `group.name`（形如 `ws_market_<id>`）聚合，分片头与帧内流标识必须严格一致；若在 `envelope_for_group` 中修改 `stream` 会破坏分片一致性与 Raw v1 格式兼容性。
   - 最终采用更加彻底且兼容的方案：保持 Raw 分片内 `envelope.stream == group.name` 满足 ADR-0010 不变；将下游消费端（`ProductCapture.persisted`、`readiness.observe_persisted`、`DepthContinuity`）优化为直接读取 `source_sequence["sourceStream"]`，彻底移除了热路径上对 `logical_envelope()` 和 `.model_copy()` 的调用。

## 关键发现与处理说明

| 检查项 / 发现 | 现状根因 | 落地改法与工程决策 |
|---|---|---|
| **`_ImmutableEnvelopeSnapshot` 防御开销** | 写入每帧时浅拷贝 `source_sequence`、创建 `MappingProxyType` 与快照 dataclass，随后又在快照上重建字典传给 CBOR 编码器。 | 直接移除 `_ImmutableEnvelopeSnapshot`，`_PreparedFrame` 直接持有 `EventEnvelope`，由 `EventEnvelope` 满足 `_EnvelopeSemantics` 协议直接传给统计与编码模块。 |
| **`EventEnvelope.canonical_mapping()` 耗时** | 原实现调用 Pydantic v2 的 `self.model_dump(mode="python", exclude_none=False)`，执行大量内部字段校验与遍历，每 10 万次耗时约 0.14s。 | 改为直接构造包含 18 个规范键的字典，耗时降至 0.038s（约 3.7x 提速），测试证实输出与 `model_dump` 产物完全一致，CBOR 编码 byte-for-byte 相同。 |
| **WS `envelope_for_group` 流名称与 `logical_envelope`** | 原计划设想在 `envelope_for_group` 填入逻辑流名，但 WS 复用连接分片头 `stream` 为 `group.name`；帧 `stream` 若不同会触发 writer 身份校验失败并破坏 Raw v1 格式。 | 保留 Raw v1 磁盘帧 `stream=group.name` 契约不变；在 `readiness.observe_persisted` 及 `persisted` 中直接读取 `source_sequence["sourceStream"]`，彻底消除热路径上的 `.model_copy()`。 |
| **REST D16 evaluated_period 二次序列化** | `coverage.py:1024` 先序列化完整 provenance，再 `json.loads` 注入 `evaluated_period`，再 `json.dumps` 重新编码覆盖 `raw_payload`。 | 前置计算 `evaluated_period` 并传入 `capture_public_response()`，在构造 provenance 记录时一次性写入，删除二次 loads/dumps。 |
| **REST 418/429 Retry-After 读取** | `_observe_rest_rejection()` 必须获取响应头以计算冷却解禁时间，原实现通过 `json.loads(result.envelope.raw_payload)` 反序列化读取 headers。 | `RestObservation` 增加 `response_headers` 字段直接暴露响应头字典，`_observe_rest_rejection()` 直接读取该字典，完全省去反序列化。 |
| **REST 线程池写盘碎片化** | 每次 REST 轮询完成后各自调用一次 `persist_rest`，串行进出线程池执行单帧 `drain_all`。 | 保持 418/429 冷却门同步生效后，在 `persist_rest` 中引入按 spool 键合并等待队列，并发写入共享单次线程池 `drain_all`，异常与完成状态精确传播。 |
