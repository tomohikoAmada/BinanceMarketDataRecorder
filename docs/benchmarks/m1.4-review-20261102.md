## 接续实现与回归证据

- Writer 保留 `_PreparedFrame` 作为一次有界写入的 bytes、envelope 引用、ordinal 与连接转换记录；
  它不再充当 EventEnvelope 包装器。直接调用 `encode_frame(envelope)` 和
  `ChunkStatistics.add(prepared.envelope)`。CBOR/CRC32C/SHA-256、写入后提交、失败 poison、
  周期/最终 fsync 与崩溃恢复行为沿用现有实现。
- 受控调用方在 append 完成前不修改内部元数据；不为内部并发篡改额外复制字典。
  append 返回后的对象复用已验证不会改写磁盘 bytes 和已提交统计。
- 在原 `9915c83` 的 coverage 模块上执行新增 `outcome=error` 回归，确实捕获
  `Future exception was never retrieved`；修正后相同测试通过。
- 并发测试覆盖正常三条请求合并、worker 已启动后到达的请求、共享写盘异常、取消主调用方、
  取消等待方。主调用方取消仍等线程退出后才释放所有权；等待方取消不终止其他请求的刷盘；
  所有结束路径清空批次等待状态，不遗留未读取异常。
- `test_raw_chunk_golden.py` 新增实际 RawChunkWriter 输出，以及真实封存 `.zst` 解压后内容与冻结 golden 的逐字节比较。
  已有 clean seal 的增量 evidence / 独立扫描差分、随机样本、短写和恢复回归继续验证 `.zst`
  及 manifest；Go golden 工具未修改，默认命令独立校验同一冻结向量的 framing/CRC。
  另执行真实 Writer → seal → `.zst` 解压，将新内容写入临时工作目录的
  `tests/golden/raw_chunk_v1.json`，再从该目录运行原 Go 工具的绝对路径：
  **773 Raw bytes / 1 frame** 校验通过。临时输入含新 chunk ID/时间和
  `event(500, payload=b'{ "u": 500, "extra": "M1.4" }')`，不是仓库冻结向量；
  Go 覆盖 framing/CRC，Python 覆盖 canonical CBOR、完整 metadata 与 manifest。
- 正常 WS 逐帧消费不做逻辑流复制；序列缺口追加 capture flag、低频快照适配等必要复制仍保留。
  不能将这一优化描述成整个系统完全零分配或所有路径都没有 `model_copy`。
