## 发现与修正

| 发现 | 影响 | 修正 |
| --- | --- | --- |
| `live_raw_verification_enabled` / 环境变量仍能启用采集期每 10 秒重验 | 只做到默认关闭，仍保留计划要求移除的实时后台重验循环 | 删除配置、环境变量、Runtime 创建和等待该任务的代码；独立校验函数与原有离线 worker 保留 |
| `_CompressionResult` 继承 tuple 又附加属性，调用方通过 `getattr` 探测；`TypeError` 时重试压缩，缺摘要时回读；manifest 参数默认为 `0` / 空摘要 | 为内部测试替身增加生产回退，可能掩盖真正的 TypeError 并再次触发磁盘操作 | 普通 dataclass 返回明确的大小和摘要，单次调用、单次源摘要比较；manifest 必须显式接收大小和摘要；更新旧测试替身 |
| 新增 `verify_readback` 开关让正常封存重新走全文件回读 | 为旧的 readback 故障用例保留已取消的封存阶段 | 删除开关及新分片回读分支，移除该阶段的旧故障用例；保留独立校验和崩溃恢复测试 |
| `_HashingWriter.write()` 按请求长度累计哈希，只调用一次无缓冲 `write` | 短写时压缩产物不完整，最终大小检查报错，无法完成本可继续的封存；原实现不会把这种错误产物标为 SEALED | 用简单写满循环处理短写，成功后累计大小与摘要；无进展即报错并保留源文件。7 字节短写回归在原逻辑下复现 `compressor stored byte count mismatch`，修复后产物独立逐帧验证通过 |
| 原 runtime 测试关闭了全部创建的协程，再期待任意 RuntimeError | 没有证明正常服务进入采集阶段后不存在重验任务 | 使用既有 FakeCollector / power / sleep fixtures，真实运行 ServiceRuntime 到 RUNNING，再优雅停止；只替换日报 worker 的实际子进程执行，确认仅构造日报 worker、无 Raw 重验任务 |

保留 `_HashingReader` 对压缩源的流式 SHA-256：它利用压缩必需的 `.partial` 读取，
不增加独立扫描。CRC32C 和 Writer 未压缩 SHA-256 继续在帧写入时计算。
封存新 `.zst` 时仅压缩写盘、fsync、原子重命名及登记；**压缩文件的全文件解压读取为 0 次**，
并不意味着无需读取未压缩 `.partial`。

已存在 `.zst` 的幂等恢复路径仍读取并核对其身份，避免崩溃后错误采用孤立产物；
`spool/recovery.py` 的截断恢复、跨盘归档验证及手动独立校验继续保留。
Raw v1 格式与校验器协议没有变化。未新增后台扫描、额外文件或新的抽象层。

## 验收覆盖

- `test_stream_rotation_and_stop_never_open_compressed_raw_for_reading`：实际 StreamSpool
  超过 1 MiB 触发大小轮换，再写入另一帧并优雅停机；期间拦截 `Path.open`，禁止读取
  `.zst` / `.zst.partial`，完成后独立验证两份产物的帧、统计、双摘要和 Catalog。
- 原 Writer / `seal_partial` 零回读测试继续通过，未压缩源变更与现存 SEALING / SEALED
  崩溃边界测试适配新返回类型后继续检查，不增加生产兼容分支。
- `test_cli_verify_raw_command`：实际 CLI 首次校验通过后，修改同一个压缩文件末字节，
  再执行 `verify-raw --chunk-id <UUID>`；必须处理该分片、检出损坏并返回退出码 `2`。
- `tests/integration/test_p3_verification.py` 保留压缩截断、CRC 错误、统计和身份不符等独立
  校验用例；`tests/fault_injection/test_recovery.py` 保留 `.partial` 截断恢复与校验和损坏隔离；
  seal 崩溃边界和归档事务回归同时运行。

`verify-raw` 默认有界处理待校验队列，**不会自动重扫已经校验过的历史分片**；
指定 `--chunk-id` 会重新入队供本次手动检查，复用现有实现。
大分片或大量抽检应调整已有 `--max-files` / `--max-bytes` / `--max-seconds` 预算。
