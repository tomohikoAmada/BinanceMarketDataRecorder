# M2.1 独立复核与执行记录（2026-11-02）

## 结论与范围

复核基点：`main` `d3507f61c3c907b30960bc258f3fb409559c5d01`，工作区干净。
根据 `production_milestone_plan.md` 与 `AGENTS.md` 的要求，任务 `M2.1` 目标为**彻底移除学院派过度防御**：
1. 取消实时采集封存（`seal`）后的全文件解压回读（Readback）；
2. 取消实时采集期间后台每 10 秒发起一次的独立子进程重验循环（`verification_worker`）；
3. 保留并适配非实时场景的独立全文件校验能力（崩溃 `.partial` 恢复、归档拷贝删源前校验、运维手动 `verify-raw` CLI 离线抽检）。

本次改动仅针对 `M2.1` 涉及的代码路径、新增 CLI 子命令、配置开关与对应测试用例，未提前修改 M2.2（启动空分片）、M2.3（双栈合并）或 M2.4（模块拆分与延迟导入）。

## 现状瓶颈与具体改造核对

| 项目 | 优化前现状（`d3507f6`） | M2.1 改造实现 |
|---|---|---|
| **封存后全文件解压回读** | 在写入期已通过 `CRC32C` 与 `SHA-256` 保证数据完整性的前提下，`_seal_verified` 在每次封存新分片后立即调用 `_artifact_identity(target_partial)`，将刚写完并 `fsync` 的 `.zst` 文件完整重新读出并用 `ZstdDecompressor` 解压校验一遍。 | 在 `_compress` 中引入 `_HashingReader` 与 `_HashingWriter`，在单次流式压缩写盘时同步计算未压缩 SHA-256（读端校验）与压缩后 SHA-256 及大小（写端记录），返回 `_CompressionResult`；`_seal_verified` 默认零回读（`verify_readback=False`），不再重读或解压磁盘上的 `.zst` 文件，将解压读取次数直接降至 **0 次**。 |
| **后台周期性全文件重验循环** | `ServiceRuntime.run()` 每 10 秒通过 `DailyReportWorker` 启动一个独立 Python 子进程运行 `service/verification_worker.py`，遍历 `Catalog` 中的 `pending_raw_verifications`，对所有新封存分片再次执行全文件解压与逐帧 CBOR 字段核验。 | 在 `RecorderConfig` 增加 `live_raw_verification_enabled: bool = False`（默认关闭，支持通过环境变量 `BINANCE_MARKET_RECORDER_LIVE_RAW_VERIFICATION_ENABLED` 开启）；在采集守护进程中默认关闭该后台重验子进程循环，彻底消除采集运行期对磁盘 I/O 和 CPU 的周期性争抢。 |
| **`RawChunkWriter.seal()` 入口** | `RawChunkWriter` 仅有 `close()` 与内部证据提取方法，封存逻辑全部分布在 `StreamSpool` 与 `spool/seal.py`。 | 在 `RawChunkWriter` 新增 `seal()` 成员方法，直接桥接 `_seal_clean_writer`，与计划书符号约定保持一致。 |
| **按需保留独立读取校验场景** | 场景分散，CLI 仅有 `binance-market-recorder verify new`，缺乏直接的 `verify-raw` 命令。 | 保留 `spool/recovery.py` 对残留 `.partial` 的截断恢复与 `validate_sealed_artifact`、保留 `archive/manager.py` 在跨盘归档删除本地分片前的 `validate_sealed_artifact`；在 CLI 正式提供 `binance-market-recorder verify-raw` 子命令，供运维人员手动发起离线抽检并检出任何篡改或损坏。 |
