# M2.2 独立复核与实施记录（2026-11-02）

## 复核结论与范围

本轮工作针对 [`docs/production_milestone_plan.md`](../production_milestone_plan.md) 中的任务 **`M2.2`：取消启动时每流 0 记录空 `.zst` 分片（更新 `ADR-0038`）** 进行实施与独立复核。

目标是彻底移除每次采集进程启动时为数十/上百个流写入 0 记录空 `.zst` 分片和 `.json` manifest 的过度防御行为，消除服务重启时的文件与 `fsync` 风暴，同时保持对进程边界、重连分界和数据完整性的严格检验与回放兼容。

## 关键发现与实施修正

| 计划项 / 观察项 | 现状与实际代码定位 | 实施与修正方式 |
| --- | --- | --- |
| 计划提及的目标文件 `models/manifest.py（RawChunkManifest）` | 经代码库全面检索，不存在 `models/` 目录或 `RawChunkManifest` 类；manifest 的构建与严格 schema 校验均在 [`src/binance_market_data_recorder/spool/seal.py`](../../src/binance_market_data_recorder/spool/seal.py) 中。 | 在 `spool/seal.py` 中扩展 `MANIFEST_OPTIONAL_FIELDS = frozenset({"process_boundary_before_first_frame"})`，并在 `parse_strict_manifest_bytes()` 中严格断言其为布尔值；未知字段依然拒绝。 |
| 进程启动事件记录 | [`service/runtime.py:975`](../../src/binance_market_data_recorder/service/runtime.py#L975) 在启动时已有全局 `SERVICE_STARTED` Catalog 事件落盘。 | 无需冗余重复插入多条启动事件，直接保留 Catalog 单一操作事件，满足全局启动边界标记。 |
| 启动时每流生成 0 记录分片 | [`spool/stream.py`](../../src/binance_market_data_recorder/spool/stream.py) 中的 `seal_capture_startup()` 在启动时为每个流写出 0 记录分片。 | 将 `StreamSpool.seal_capture_startup()` 调整为无操作（返回 `{}`，写出 0 个磁盘文件），各 collector 在启动时不再触碰磁盘，磁盘上的空分片数为 **`0`**。 |
| 首分片 manifest 标记与单次传递 | 每个流首次收到数据后封存的首个真实分片需携带启动边界证据，后续分片不得携带。 | 在 `StreamSpool` 初始化时设置 `_process_boundary_pending = True`；封存首个非空分片时通过 `_seal_clean_writer()` 传入 `process_boundary_before_first_frame = True`，并在封存成功后清除 pending 标记；次分片及后续分片均不包含该字段。 |
| 崩溃恢复保留边界标记 | 若进程在首分片 SEALING 期间崩溃，恢复时需保留该启动边界标记。 | 在 `Catalog` 的 `ChunkState.SEALING` 状态流转 evidence 中持久化 `process_boundary_before_first_frame: True`；在 `spool/seal.py` 的 crash roll-forward 和 `seal_partial()` 中保留并传递该标记。 |
| 重连分界判定兼容 | [`audit/reconnect_boundaries.py`](../../src/binance_market_data_recorder/audit/reconnect_boundaries.py) 原依赖 0 记录空分片识别进程边界，否则新旧连接跳变会误报为 `UNMARKED_RECONNECT`。 | 在 `_classify_inter_chunk()` 中增加对新分片 manifest `process_boundary_before_first_frame: True` 的识别；若存在该标记，确认两分片跨越进程启动，判定为 `EXPLICIT_SEQUENCE_GAP`；同一进程内后续发生的未标记重连依然严格判定为 `UNMARKED_RECONNECT`。 |
| V5 重连投影适配 | [`service/acceptance_v5_reconnect.py`](../../src/binance_market_data_recorder/service/acceptance_v5_reconnect.py) 中的 `manifest_projection()` 投影白名单。 | 在 `manifest_projection()` 中保留并传递可选的 `process_boundary_before_first_frame` 字段，确保重连审计与验收链路正常接收。 |
