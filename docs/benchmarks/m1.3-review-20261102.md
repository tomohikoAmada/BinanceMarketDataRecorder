# M1.3 独立复核与接续记录（2026-11-02）

## 结论与范围

M1.3 的原实现方向符合计划，但初始工作区还不能签收。保留既有收盘过滤、S12 六周期和 Seed 退役功能，补齐缺口后按本记录验收。未推进 M1.4、M2、VPS 部署或生产资格认证。

核查链路包括配置/产品发现 → WS 分组及帧验证 → 有界接收与 Writer → REST 调度/共享预算 → Raw/Catalog/可用性 → 规范化与回放。Raw v1 与现有单份 REST provenance 格式保持不变。

## 发现与修正

| 发现 | 接续结果 |
| --- | --- |
| 形成帧只 `ensure()`，没有记录有效观测，且旧错误可能残留 | 更新内存 `last_success`、有效观测与过滤计数，清除已恢复的帧错误；时钟未知窗口保留 |
| 重连判断用了上一根 bar 的收盘边界，可能请求当前形成中的 bar | 从下一根预期 open 推导已闭合边界，只请求完整缺失区间 |
| 长缺口只请求一页；请求中发生新 gap 会丢失；失败后水位仍向前 | 每源保留合并的待补区间，每次最多 100 bar，只有连续闭合前缀推进游标；失败/空响应五秒后重试 |
| 补采绕过现有 REST 并发管理，错误只日志输出，可能掩盖写盘故障 | 复用现有调度槽、共享预算及 418/429 冷却；失败响应也保留 Raw，存储错误直接向监督器传播 |
| UTC+8 月线按 UTC 月初运算 | 按本地月边界推进，覆盖跨年与闰月 |
| 连续合约按最后一个下划线切分，破坏 `CURRENT_QUARTER` | 按第一个下划线分离 pair 与完整 contractType |
| Seed 水位包括形成中 bar；continuous seed 名称映射错误 | 仅使用请求返回时已闭合的行，正确映射 `continuous_seed_*` |
| 已完成 RPI seed 退役后按需快照不能重新调度 | 快照请求将它重新激活，完成后再次退役 |
| 自定义 `SourcesView(dict)` 包装重复维护字典接口且类型检查失败 | 使用标准库 `ChainMap` 连接两张状态表，无自定义容器 |
| 新增测试使用仓库没有安装的异步 pytest 插件 | 改用项目现有 `asyncio.run()` 模式，无新增依赖 |

原实施记录的全过滤批次越界、局部变量清理、过滤后进度计数、基准等待与请求预算键修复均保留。指数 K 线的真实样本 `k.s` 可为 `"0"`，因此未套用普通 K 线的 symbol 强校验；真实样本回归继续通过。
