## 3. 生产配置文件规范与策略落实

生产配置文件部署模板为 [`deploy/recorder.toml`](../../deploy/recorder.toml)（宿主机目标路径为 `/etc/binance-market-data-recorder/recorder.toml`），内容落实了 Owner 锁定的全部六项关键决策：

```toml
[recorder]
data_root = "/var/lib/binance-market-data-recorder"
capacity_profile = "vps-production-v1"
network_proxy_mode = "direct"
log_level = "INFO"
# M1.1: 15-minute / 128 MiB chunk rotation policy
rotation_seconds = 900.0
rotation_bytes = 134217728
durability_interval_seconds = 1.0
ingress_queue_capacity = 8192
max_frame_bytes = 16777216
heartbeat_seconds = 5.0
sleep_gap_threshold_seconds = 30.0
prevent_sleep = false

[recorder.coverage]
underlying_assets = ["BTC", "ETH"]
# ADR-0055 / D1: dated premium klines omitted prospectively; perpetual retained
capture_dated_premium_klines = false
# ADR-0057: USD-M delivery adlQuantile returns HTTP 400 / -1121; omitted prospectively
capture_dated_adl_risk = false
# ADR-0058 / D1: only persist closed kline bars; missing bars backfilled via REST
kline_forming_policy = "closed_only"
# ADR-0058 / D2: S12 covers only the 6 distinct timezone intervals; 10 covered by S11
spot_utc8_intervals = ["6h", "12h", "1d", "3d", "1w", "1M"]
# ADR-0054 / P2: D06 historicalTrades cadences & steady derivative rate limits
recent_trades_interval_seconds = 30.0
max_steady_derivative_weight_per_minute = 1000.0

[recorder.coverage.recent_trades_intervals]
# 19 个 BTC / ETH 衍生品物理轮询周期（实测 2s USDT / 3s USDC / 30s COIN-M）
"cm_delivery:BTCUSD_261225" = 30.0
"cm_delivery:BTCUSD_270326" = 30.0
"cm_delivery:ETHUSD_261225" = 30.0
"cm_delivery:ETHUSD_270326" = 30.0
"cm_perpetual:BTCUSD_PERP" = 30.0
"cm_perpetual:ETHUSD_PERP" = 30.0
"um_delivery:BTCUSDT_261225" = 30.0
"um_delivery:BTCUSDT_270326" = 30.0
"um_delivery:ETHUSDT_261225" = 30.0
"um_delivery:ETHUSDT_270326" = 30.0
"um_perpetual:BTCU" = 30.0
"um_perpetual:BTCUSD1" = 30.0
"um_perpetual:BTCUSDC" = 3.0
"um_perpetual:BTCUSDT" = 2.0
"um_perpetual:ETHBTC" = 30.0
"um_perpetual:ETHU" = 30.0
"um_perpetual:ETHUSD1" = 30.0
"um_perpetual:ETHUSDC" = 3.0
"um_perpetual:ETHUSDT" = 2.0
```

### 关键策略机制核对：
1. **轮换与缓冲**：`rotation_seconds = 900.0`（15 分钟）配合 `rotation_bytes = 134217728`（128 MiB），中低频流封存率下降 ~90%，单分片大小受限保护内存；独立 1.0 秒 durability `fsync` 确保崩溃丢失窗口不超过 1 秒。
2. **K 线落盘与补采（ADR-0058 / D1）**：`kline_forming_policy = "closed_only"`，未收盘帧（`k.x == False`）在内存刷新存活水位但不写 Raw；断线漏收收盘 bar 后台自动通过共享请求预算发起有界 REST 补齐并写入真实接收时间。
3. **S12 去重（D2）**：`spot_utc8_intervals` 显式锁存 6 个独特周期，重合的 10 个周期由 S11（UTC）覆盖，双币种直接节省 600 个流。
4. **SQLite Catalog 策略（ADR-0059 / D3）**：底层连接统一启用 `WAL + NORMAL`，健康源刷新通过共享水位表合并，消除每 10 秒数千行写入放大；不可逆删除保留 `FULL` 屏障与 WAL checkpoint。
5. **豁免源透明性**：`capture_dated_premium_klines = false`（ADR-0055）与 `capture_dated_adl_risk = false`（ADR-0057）显式声明，避免无谓 HTTP 400 失败。

## 4. 非侵入式外部观测脚本（`tools/observe_vps_recorder.py`）

新增的观测脚本满足以下严格要求：
- **纯只读与非侵入**：不获取任何 SQLite 写锁，不修改数据目录任何文件，不干扰主进程事件循环。
- **采集指标**：
  1. `systemctl show`：服务单元 `ActiveState`、`SubState`、`MainPID`、`InvocationID`、`NRestarts`、`Result`、`MemoryCurrent` 及 `CPUUsageNSec`。
  2. 进程 CPU/RSS：优先从 Linux `/proc/<pid>/stat` 与 `/proc/<pid>/statm` 读取精确滴答计数与页内存，跨平台兜底使用 `ps` 命令；自动计算采样周期间的 CPU 百分比（`cpu_percent`）。
  3. 服务运行与 Catalog 状态：通过只读调用 `binance-market-recorder status` 解析 `sealed_chunks`、`active_chunks`、`space_severity` 与网络健康。
  4. 存储容量：通过 `os.statvfs` 读取真实剩余空间（字节数、GB 及使用百分比）。
  5. Raw 分片增长率：扫描 `raw/` 目录统计已封存 `.zst`、活跃 `.partial` 与 manifest 数，计算小时级分片生成速率（`chunks/hour`）与字节速率（`MB/hour`）。
- **执行方式**：
  - 单次快照：`python tools/observe_vps_recorder.py --once` 或 `scripts/observe-recorder --once`
  - 持续采样输出 JSONL：`python tools/observe_vps_recorder.py --interval 10 --output /var/log/recorder-observer.jsonl`

## 6. 发现的问题与平台运行边界（Notes & Platform Boundaries）

在执行 M3.3 期间，发现并明确标注以下边界与环境差异：

1. **macOS 与 Linux VPS 数据根路径权限边界**：
   - 生产配置文件 `deploy/recorder.toml` 中的 `data_root = "/var/lib/binance-market-data-recorder"` 是专为 Linux VPS 系统服务设计的标准路径（由 systemd 安装流程以 root 身份创建并授权给无特权服务用户）。
   - 在 macOS 本地开发环境下直接运行 `binance-market-recorder --config deploy/recorder.toml doctor` 时，`data_root_parent_access` 检查会因为 macOS 下普通用户无权写入系统根目录 `/private/var/lib` 而报告 `FAIL`。而在 Linux VPS（Ubuntu 24.04）上通过预置创建后则正常通过。在 macOS 本地执行无参数 `doctor` 时，系统自动使用用户的 `~/Library/Application Support/` 并 100% 通过检查。
2. **`vps-production-v1` 禁止环境变量覆盖**：
   - 配置项 `capacity_profile = "vps-production-v1"` 时，系统严格禁止通过 `BINANCE_MARKET_RECORDER_*` 环境变量覆盖配置（如尝试通过 `BINANCE_MARKET_RECORDER_DATA_ROOT` 改写路径会抛出明确的配置拒绝错误），这是 ADR-0028 锁定的安全契约，防止 co-resident 进程或外部环境篡改数据路径。
3. **外部观测脚本的跨平台兼容性**：
   - `tools/observe_vps_recorder.py` 在 Linux VPS 上可直接利用 systemd bus/properties 与 `/proc` 文件系统获取最高精度的进程与服务状态；
   - 在 macOS 本地运行（未安装 systemd）时，脚本已内置平滑降级处理：`systemctl` 缺失时记录 `available: false, error: "systemctl_not_found"`，进程指标自动切换至 `ps` 解析，保证测试和离线运行不崩溃。
4. **Python 3.12 多线程 fork 警告说明**：
   - 离线全量回归中的 13 条警告来自历史测试套件（`test_archive_kill9.py` 5 条，`test_catalog_snapshot.py` 8 条）中针对多线程进程使用 `os.fork()` 的 Python 3.12 弃用提示，并非业务代码缺陷，未引入任何新警告。
