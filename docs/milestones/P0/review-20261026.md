## R1 · 中优先级：排序后核对掩盖实际写入乱序

位置：[PR #86 的 steady_baseline.py](https://github.com/tomohikoAmada/BinanceMarketDataRecorder/blob/004c1a60096efeaebc612d33f132c0bda2f1a14a/docs/milestones/P0/steady_baseline.py#L400)，400–424 行；尤其 402–408 行。

核对器先按 `receive_monotonic_ns` 给所有记录重新排序，再和输入摘要比较。因此，同一连接的帧若收到顺序为 1、2、3，却被 writer 写为 2、1、3，只要各帧带着原接收时间，当前比较仍通过。注释还把 `load_source_chunks` 说成按流时间排序，实际该 helper 按内容哈希 / chunk ID 排序。

本次使用真实 `RawChunkWriter`、`seal_partial`、`load_source_chunks`、`iter_source_records`，在独立临时目录写入三个合法测试事件，物理顺序为 2、1、3。完整文件读取及校验成功；直接比较物理原文顺序为 false，执行基准中的排序后比较为 true。接收单调时间依次为 `[5000000002, 5000000001, 5000000003]`。没有访问生产数据。

影响：P1 正要修改批量写入和并发处理，这个核对器会遗漏一类相关回归。现有结果可以支持原文内容与数量核对，不能凭该步骤证明物理写入顺序从未改变。

- [x] **修正 / 通过条件（已按末尾证据完成）：**保留物理帧 ordinal，先独立检查同一连接 / 流的写入顺序，再按明确的 chunk 生命周期拼接核对输入；需要排序的回放语义与原始写入顺序分开报告。增加 2、1、3 乱序应失败、正确跨分片顺序应成功的短回归。不要仅把 sort 换成另一个按帧内容重排的 sort。

## R2 · 中优先级：计时窗口之外补做的工作没有从性能结论中区分

位置：[PR #86 的 steady_baseline.py](https://github.com/tomohikoAmada/BinanceMarketDataRecorder/blob/004c1a60096efeaebc612d33f132c0bda2f1a14a/docs/milestones/P0/steady_baseline.py#L364)，364–377 行及 459–467 行。

### R2剩余：一次积压回落会掩盖整体增长

位置：[PR #87 的 benchmark_checks.py](https://github.com/tomohikoAmada/BinanceMarketDataRecorder/blob/43aab9fd2475555db1951ec0cbdba1ce24c6ed17/docs/milestones/P0/benchmark_checks.py#L222)，222–225行。`classify_steady()`要求五个边界的积压全部单调不减，才报告持续增长。批量writer中途消化一小批数据很正常；只要其中一个边界下降，这个条件就完全不成立，即使后续积压反复扩大、结束时还有大量输入未写入。

本次用真实`WorkloadProgress`计数接口及当前分类器构造一个确定性短例，所有输入在20s协议期限前已送完，written/persisted随批量处理推进：

| 边界elapsed | sent / received / enqueued | written / persisted | pending write |
| --- | ---: | ---: | ---: |
| 4 | 4 | 4 | 0 |
| 8 | 8 | 5 | 3 |
| 12 | 12 | 10 | 2 |
| 16 | 16 | 11 | 5 |
| 20 | 20 | 12 | 8 |

实际返回`status=STEADY, performance_comparable=true, reasons=[]`。窗口结束有40%的输入尚未写入；尾部再写完并fsync到20帧也不会改变该错误判定。原19项回归仍全部通过，说明缺少这个分支。复现核心（仓库根目录，`.venv/bin/python`）：

```python
from docs.milestones.P0.benchmark_checks import WorkloadProgress, classify_steady

key = "spot/BTCUSDT/book_ticker"
p = WorkloadProgress({("spot", "BTCUSDT", "book_ticker"): [b"x"] * 20},
                     {"book_ticker": 1.0})
points, sent, written = [], 0, 0
for i, (target_sent, target_written) in enumerate([(4, 4), (8, 5), (12, 10),
                                                 (16, 11), (20, 12)]):
    while sent < target_sent:
        for phase in ("sent", "received", "enqueued"):
            p.record(phase, key, 1, float(sent))
        sent += 1
    while written < target_written:
        p.written("writer", key, 1)
        written += 1
    p.synced("writer", p.sync_target("writer"))
    points.append(p.snapshot(float((i + 1) * 4)))
print(classify_steady(points, 20))  # PR #87版本错误地返回STEADY；v4返回NON_STEADY
```
