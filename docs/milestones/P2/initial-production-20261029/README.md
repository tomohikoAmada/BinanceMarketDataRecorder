## 配置与调度

[首版候选配置](recorder.toml)沿用195762c已接受配置的D06频率、全部原生周期、
WS范围和准入上限，仅显式设置`capture_dated_premium_klines = false`。
库默认值为true，旧配置继续生成完整目标；旧测量配置和文件未改写。此文件尚无
生产运行资格，实际运行前仍需选择授权的内部数据目录并完成P3–P6。

源生成按`um_delivery`/`cm_delivery`身份，只跳过D23的premium K线，发生在
预算准入和SourceState创建之前。没有轮询、失败重试或后置丢弃；新发现交割产品
使用同一规则。永续premium、交割mark/index、共享pair关联及其他源的完整描述
与完整目标逐项相同。没有通用排除框架、另一价格替代、生产HTTP接入或新限流器。

## 覆盖与生效边界

现有`selected-asset-coverage.v1`增加`source_selection`：当前已准入产品、配置周期内的完整目标
数、已选数、目录数、WS/REST数、名义请求预算，以及逐产品/周期的`uncaptured_sources`。
暂缺项为`OWNER_APPROVED_UNCAPTURED`、`official_applicability=UNKNOWN`、
`continuity_eligible=false`，不能视为成功或交易所不提供。未准入产品仍由原
`capture_status`显示预算/目录限制，不能混入已准入产品的计划数。

`effective_from_utc_ns`和`collector_instance_id`标识这份配置从新owner实例创建开始
生效；目录观察事件保存同一配置、选择报告和实际源计划。运行中不修改配置以删除
失败源；变更配置使用新实例和新连续性窗口。已选计划数包含等待生命周期触发的D31，
不等同于瞬时活跃请求数。报告在目录调和时更新，常规status不重建完整源计划。
旧Raw、失败、目录证据及旧分母不变；未来99.5%只对该配置的适用/启用源考核，
不能称为完整目标已覆盖，也不在P2宣称已获得连续性资格。
