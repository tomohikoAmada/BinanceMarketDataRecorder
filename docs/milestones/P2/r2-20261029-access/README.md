# P2-R2：交割溢价指数 K 线的权限与重要性

2026-10-29。按 owner 的问题核对官方接口说明、权限、错误码和 Python SDK，
并做六次无凭据公开 GET。本次仅研究解释；不更改采集范围、配置或验收状态。

## 结论

**当前证据不支持“缺 API Key 或 VIP 资格”这一解释。** 两个原生 premium 接口
的文档没有要求 API-key header、签名或 VIP；同接口的永续请求匿名成功。
不能从“Market Data 页面”这个分类名推断需要 MARKET_DATA 权限：后者是另一种
明确的安全标签。例如历史逐笔接口明确要求 key，这项 premium 接口没有该要求。

**文档列出了接口，但没有明确承诺所有交割合约都支持它。** 产品目录有效，
表示存在这个合约；每一种统计指标是否适用，还需要该接口自己的规则。
UM/CM 跨市场迁移说明也没有明确建立永续/交割的指标适用范围。
因此目前不能认定“官方承诺交割有数据、实现却坏了”，也不能认定永久不提供。

## “核心数据”的工程判断

普通K线保存价格的开、高、低、收；这里保存交易所发布的溢价指数的开、高、低、收。
官方示例中的值约为-0.0004，而不是BTC成交价格。这是一条独立的官方指标历史。
不要把它与普通价格K线、标记价格、指数价格或自行计算的价差视为等价数据。

对保存成交、盘口、产品身份、时间和序列等基本市场事实，它不是采集运行的依赖。
就先保证这些基本事实稳定保存而言，可以讨论降低这项未明确适用的交割指标的
上线优先级；这是工程取舍，不是官方将其定义为“不重要”。若未来研究直接需要
这条官方序列，它就是关键输入，不能保证用其他数据或事后下载精确补回。
永续 premium 本轮可以匿名取得，应继续按现有范围保留。

当前完整目标仍包括这项交割指标。owner 尚未接受暂缺例外，本研究不将该项标成
不适用或完成，不停用失败源，也不发布此前准备的官方 issue。R1/R4结论不变，
R2/P2仍开放，P3未开始，无生产操作。
