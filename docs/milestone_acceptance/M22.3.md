# M22.3 Acceptance — Local receive / verify / durable publish / receipt

## Result

M22.3 is **IMPLEMENTED** on the dedicated feature branch. This record covers
implementation-branch evidence only; it does not claim merge, production
deployment, remote deletion authorization, or production readiness.

The implementation reuses the exact `RemoteSourceSelection` produced by M22.1
and performs no source selection, Catalog write, archive transaction creation,
ChunkState transition, source mutation, or source-manifest mutation. A minimal
`StoredByteProvider` supplies only a bounded stored-byte stream. The caller
selects a `RemoteReceiveTarget` containing the Archive Set and registered
physical-medium identity.

## Durable local authority chain

On supported Linux and macOS filesystems the receiver binds/revalidates the
M22.2 medium, establishes only the direct `raw/`, `manifests/`, and
`archive-set/receipts/` directories, and commits immutable facts in this order:

```text
exact M22.1 descriptor + exact source Raw manifest
  -> exclusive same-directory Raw receive temp
  -> exact byte-count and post-count EOF check
  -> file fsync, close/reopen streamed full readback, size/SHA-256
  -> exclusive Raw publication, raw/ fsync, final revalidation
  -> external-archive-manifest.v1 publication and manifests/ fsync
  -> unchanged archive-set-entry.v1 commit and exact readback
  -> remote-archive-receipt.v1 file fsync and exclusive publication
  -> archive-set/receipts/ fsync
  -> independent full-chain revalidation
```

The Raw receive temporary uses an unpredictable invocation-owned
`.receiving` name with `O_CREAT|O_EXCL`; unknown `.receiving` and `.partial`
files are retained and ignored. Final publication reuses M22.2's actual
Linux `renameat2(RENAME_NOREPLACE)` / macOS `renameatx_np(RENAME_EXCL)` helper.
No immutable winner is overwritten. Authority-sensitive reads use no-follow
descriptor opens plus regular-file checks; Raw hashing is bounded streaming
I/O.

The local archive manifest remains `external-archive-manifest.v1`. It embeds
the exact original `raw-chunk-manifest.v1` bytes and parsed object. Its exact
digest is the Archive Set entry's `archive_manifest_sha256`; the embedded
source manifest digest is the separate `source_manifest_sha256`. No standalone
source-manifest copy is written. The archive manifest transaction UUID is
deterministic over the versioned M22.1 descriptor digest, `archive_set_id`,
`storage_id`, and final artifact path, and is independent of receipt session
and retry time. Existing semantically identical manifests may be adopted with
their original verification timestamp and exact bytes.

## Receipt and revalidation

`remote-archive-receipt.v1` has exactly the frozen M22.3 fields. The caller
supplies a canonical UUID4 `session_id`. `receipt_id` is SHA-256 over canonical
receipt identity fields excluding `receipt_id`, so one chain/session is
idempotent and a different session creates a distinct receipt without changing
the stable receive transaction.

`revalidate_remote_archive_receipt()` requires the exact M22.1 selection and
proves receipt canonical identity, current registered physical marker,
Archive Set medium, exact entry digest, exact external-manifest digest and
identities, embedded source-manifest bytes/digest, transitive source descriptor
binding, and final Raw full size/SHA-256. It does not use the workspace SQLite
index and still succeeds after that index is removed. Mere pathname existence
is never sufficient.

The fault seam names K0 through K12. Spawned-process abrupt-death tests
materialize partial/unfsynced temp, fsynced temp, Raw visible before parent
fsync, durable Raw, archive manifest visible before parent fsync, durable
manifest, durable Archive Set entry, receipt fsynced temp, receipt visible
before parent fsync, and fully durable receipt states. K0 through K11 never
return a committed receipt; a new invocation safely converges from every
state. K12 is the first boundary at which receipt-parent durability is
complete. Separate injected failures cover artifact, Raw-parent, manifest,
manifest-parent, Archive Set entry, receipt, and receipt-parent commit paths.

Windows end-to-end M22.3 durability fails closed before receive. No receipt is
returned on an unsupported platform or failed durability primitive.

## Non-scope and compatibility

M22.3 does not implement deletion authorization, `REMOTE_DELETE_PENDING`,
`REMOTE_DELETED`, remote Catalog persistence, CASE A/B/C/D remote recovery,
VPS source unlink, SSH, `RemoteTransport`, or Catalog snapshots. M22.4A and
later remain not started. The live Catalog schema, `ChunkState`, `ArchiveState`,
`ARCHIVE_CHUNK_STATES`, `archive_transactions`, Raw/EventEnvelope and source
manifest schemas, registered-storage marker, Archive Set medium/entry schemas,
CLI, and M10 same-host semantics are unchanged.

Rollback reverts the additive receiver/API/tests/docs only. It never removes
already-published local Raw, manifests, Archive Set entries, receipts, source
Raw, or source manifests.
