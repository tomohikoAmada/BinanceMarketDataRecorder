## Scope and authority

The observer remains the only measurement and evidence authority. It already
provides the five-minute sampling cadence, ten-minute maximum evidence gap,
Linux `CLOCK_BOOTTIME` duration authority, boot/process/service/deployment
identity checks, immutable canonical JSON publication, SHA-256 sample chaining,
resume, and transitive predecessor verification. `stage-final.json` and its
verified hash chain are the final authority after a transient unit is garbage
collected; journal output is operational corroboration.

The operator chooses one stable acceptance parent below the registered archive
directory, for example:

```text
/srv/recorder-data/recorder-archive/acceptance/m22.9/<acceptance-id>/
```

The parent must be on the registered relative path, must not be the volume
root, and must contain the identity/readiness evidence and every stage child
in the same acceptance chain. The existing stage command creates one child
named `<stage>-<uuid>` below that parent. The exact child path printed in the
stage-start evidence is recorded as `STAGE_ROOT` and is reused unchanged for
any explicit resume. A second fresh stage invocation is never a resume.

No stage is chained to another by a script or service. The primary reviewer
must verify `stage-final.json` and the eligible predecessor before an operator
explicitly starts the next stage.

## Frozen detached-unit procedure

The following procedure is descriptive and uses placeholders. It must be
performed only after the separately authorized exact-artifact and readiness
gates. It invokes the existing foreground observer; it does not start the
Recorder service. `systemd-run` intentionally omits `--wait`, `--pipe`,
`--pty`: it waits for systemd to accept the start job and for the `Type=exec`
process launch to succeed, not for the long task to finish. No collection flag
is used, so failed-unit state remains available for inspection.
The SSH command then returns while systemd continues to supervise the unit;
status and journal are inspected independently.

```bash
CONFIG=/etc/binance-market-data-recorder/recorder.toml
ACCEPTANCE_ROOT=/srv/recorder-data/recorder-archive/acceptance/m22.9/<acceptance-id>
STAGE=2h
PREVIOUS_EVIDENCE="$ACCEPTANCE_ROOT/readiness-result.json"  # 2h only
UNIT=binance-market-data-acceptance-${STAGE}-<run-id>.service

sudo systemd-run --unit="$UNIT" \
  --property=Type=exec \
  --property=User=bmdr \
  --property=Group=bmdr \
  --property=UMask=0027 \
  --property=NoNewPrivileges=yes \
  --property=KillSignal=SIGINT \
  --property=TimeoutStopSec=120s \
  --property=Restart=no \
  --property=StandardOutput=journal \
  --property=StandardError=journal \
  -- /opt/binance-market-data-recorder/venv/bin/binance-market-recorder \
  --config "$CONFIG" deployment acceptance stage \
  --stage "$STAGE" \
  --previous-evidence "$PREVIOUS_EVIDENCE" \
  --evidence-root "$ACCEPTANCE_ROOT"
```

For `12h`, `24h`, `72h`, or `168h`, `PREVIOUS_EVIDENCE` is the exact verified
`stage-final.json` from the immediately preceding stage and must be under the
same `ACCEPTANCE_ROOT`. Never use a copied or independently named predecessor.
The command's `stage-start` JSON identifies the generated child; save that
exact child path as `STAGE_ROOT` before taking any other action.

Check acceptance of the unit and retain the InvocationID before leaving the
SSH session:

```bash
sudo systemctl show "$UNIT" \
  -p Id -p ActiveState -p SubState -p MainPID -p InvocationID \
  -p Result -p ExecMainCode -p ExecMainStatus -p ActiveEnterTimestamp
sudo journalctl -u "$UNIT" --no-pager -o short-iso-precise
```

The journal is useful for operational timing and interruption evidence, but
does not replace the immutable observer records. A second SSH session may
inspect the same unit and journal; closing the first SSH session must not stop
the unit. The failed unit state is intentionally left available for inspection;
a successful transient unit may still be garbage-collected by systemd, so
`not-found` after a recorded successful exit is not evidence loss when
`stage-final.json` verifies.

To request a clean stop, use the unit only; systemd delivers SIGINT and waits
up to the bounded stop timeout. This produces retained incomplete evidence and
does not authorize a new T0:

```bash
sudo systemctl stop "$UNIT"
sudo systemctl show "$UNIT" -p ActiveState -p SubState -p MainPID -p Result
sudo journalctl -u "$UNIT" --no-pager -o short-iso-precise
```

After an interrupted stage, resume only when the recorded `STAGE_ROOT` has no
`stage-final.json`, the exact same boot ID/process incarnation/service
instance/deployment identity still holds, and every existing sample remains
within the ten-minute maximum evidence gap. Do not create a new root or invoke
the new-stage form again. Because the first command intentionally omits a
collection flag, its failed `$UNIT` may still be loaded. Before resuming, choose
a fresh unique external custody unit; changing that unit does not change the
exact `STAGE_ROOT`, original T0, original `run_id`, or immutable evidence chain,
and it must not create a second T0. Resume explicitly:

```bash
RESUME_UNIT=binance-market-data-acceptance-${STAGE}-resume-<resume-id>.service

sudo systemd-run --unit="$RESUME_UNIT" \
  --property=Type=exec \
  --property=User=bmdr \
  --property=Group=bmdr \
  --property=UMask=0027 \
  --property=NoNewPrivileges=yes \
  --property=KillSignal=SIGINT \
  --property=TimeoutStopSec=120s \
  --property=Restart=no \
  --property=StandardOutput=journal \
  --property=StandardError=journal \
  -- /opt/binance-market-data-recorder/venv/bin/binance-market-recorder \
  --config "$CONFIG" deployment acceptance stage --resume "$STAGE_ROOT"
```

Inspect the resume custody unit independently; use `RESUME_UNIT`, not the
possibly still-loaded first-run `$UNIT`:

```bash
sudo systemctl show "$RESUME_UNIT" \
  -p Id -p ActiveState -p SubState -p MainPID -p InvocationID \
  -p Result -p ExecMainCode -p ExecMainStatus -p ActiveEnterTimestamp
sudo journalctl -u "$RESUME_UNIT" --no-pager -o short-iso-precise
```

If boot, process, service, identity, path, predecessor digest or evidence
chain validation fails, leave the stage failed and preserve its files for
review. A normal `FAIL`/`INCOMPLETE` result is not automatically retried or
promoted.

Final review is read-only and must run the exact installed package against the
recorded child. For example, with `STAGE_ROOT` and `IDENTITY_PATH` set to
operator-verified paths:

```bash
sudo /opt/binance-market-data-recorder/venv/bin/python - "$STAGE_ROOT" "$IDENTITY_PATH" <<'PY'
from pathlib import Path
import sys

from binance_market_data_recorder.service.acceptance import verify_completed_stage
from binance_market_data_recorder.service.deployment_identity import load_deployment_identity

stage_root = Path(sys.argv[1])
identity = load_deployment_identity(Path(sys.argv[2]))
final, digest = verify_completed_stage(stage_root, identity)
print({"stage": final["stage"], "run_id": final["run_id"], "evidence_sha256": digest})
PY
```

Only a successful `verify_completed_stage` result and an independently
verified eligible predecessor allow the primary reviewer to authorize the
next separately named stage. No command in this procedure starts that next
stage.

The systemd references are the official primary documentation for the
