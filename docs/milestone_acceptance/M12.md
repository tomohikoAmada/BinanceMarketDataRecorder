## Architecture decisions

ADR-0017 freezes a conservative immediate-busy policy instead of canceling an
archive transaction. Users finish the existing crash-reconcilable transaction
with `archive retry` and repeat eject. Archive reservation and eject compete in
one Catalog transaction, so there is no unchecked allocation window. Both
Disk Arbitration callbacks must succeed before “可以拔出”.

The local macOS 26.5 SDK headers and PyObjC 12.2.1 metadata were inspected for
the exact asynchronous callback, dissenter and option semantics. The force
option is explicitly rejected.

## Known limitations

The M12 CLI deliberately refuses immediately while any archive transaction is
nonterminal; it provides no wait flag and never kills a worker. A crash after
persisting `EJECT_PENDING` but before system completion remains conservatively
blocked; repeat the explicit eject command, or reinsert and resolve readiness.
Disk Arbitration may refuse media eject when sibling volumes or other
processes remain active. A successful unmount followed by eject refusal is not
safe-to-remove and may leave the volume unmounted for macOS/user handling.
Persistent service-owned handle coordination arrives with the supervised
service milestones; M12 owns and closes all handles in its current CLI path.

## Data compatibility and rollback

M12 does not alter EventEnvelope, Raw chunk bytes, Raw manifests, normalized
data, or archive artifact format. It additively creates `storage_control`,
operational eject events, and `SAFE_TO_REMOVE`. Older Catalog readers that
ignore unknown tables remain valid; clients enumerating storage states must
accept the additive state.

Rollback disables the eject command while retaining passive disappearance and
reinsertion recovery. Preserve Catalog rows, Raw, archive artifacts, manifests,
and registrations. Users may use macOS eject; rollback never deletes data.
