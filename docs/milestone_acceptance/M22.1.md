# M22.1 Acceptance — Read-only remote source identity / export kernel

## Result

M22.1 is **IMPLEMENTED** on the dedicated feature branch. This record covers
the read-only source identity/export kernel only; it does not claim PR merge,
main-branch authority, or production readiness.

The implementation adds a transport-neutral `RemoteSourceExporter` that can
select one eligible source by chunk ID or the deterministic oldest eligible
source. Eligibility requires a Catalog `SEALED` chunk with no same-host
archive transaction, source and manifest paths within the exact Recorder
layout directories, a supported `raw-chunk-manifest.v1` manifest, matching
Catalog/manifest identity, exact manifest-byte hashing, and successful sealed
artifact size, stored-SHA-256, and decompressed-SHA-256 validation. A final
Catalog read rechecks `SEALED`, absence of an archive transaction, and the
unchanged source identity before returning.

## Descriptor and read-only boundary

The emitted descriptor schema is `remote-source-descriptor.v1` with exactly
these fields:

```text
descriptor_schema_version
chunk_id
market
stream
source_relative_path
stored_bytes
stored_sha256
source_manifest_relative_path
source_manifest_sha256
manifest_schema_version
chunk_schema_version
envelope_schema_version
```

Descriptor bytes are canonical UTF-8 JSON using sorted keys and compact
separators, followed by exactly one newline. The descriptor digest is the
SHA-256 of those exact bytes and is not included in the descriptor bytes. The
result also retains the exact original manifest bytes and validated source and
manifest paths.

The kernel performs no Catalog writes, source/archive filesystem mutations,
layout creation, unlink, remote transfer, receipt work, or lifecycle-state
changes. It does not add remote states or change existing Raw, manifest, or
Catalog schemas.

## Non-scope and rollback

M22.2 and later remain **NOT STARTED**. This milestone does not implement
Archive Set identity, local receive/verify/publish, receipts, remote deletion
authorization, SSH/`RemoteTransport`, Catalog snapshot transfer, CLI
commands, or deployment. Rollback is an additive code/documentation revert;
immutable Raw, manifests, and Catalog state are preserved and no source
deletion is permitted.
