## Transport and OpenSSH boundary

`RemoteTransport` exposes only selection, stored-byte opening, receipt
authorization, authority inspection, and receipt-ID deletion. The in-process
adapter delegates to `RemoteSourceExporter`, `RemoteAuthorizer`,
`RemoteDeleter`, and validated Catalog reads. Every operation after selection
is bound to the exact chunk ID and descriptor digest; it never reselects the
oldest candidate.

The OpenSSH adapter uses `subprocess` with `shell=False`, fixed remote verbs,
`BatchMode=yes`, and a bounded OpenSSH `ConnectTimeout`. It does not disable
host-key checking or known-hosts, store credentials/private keys, accept
free-form SSH options, use Paramiko/SFTP, or expose an arbitrary remote command
or path. The remote executable and optional absolute POSIX config path are
strictly shell-token-safe. Chunk IDs, descriptor digests, and receipt IDs are
validated before spawn and again by the hidden CLI.

The hidden `_remote` group has only `select-oldest`, `manifest`, `raw`,
`authorize`, `authority`, and `delete`. Payload stdout is exact and diagnostics
use stderr/nonzero exit. Receipt bytes travel unchanged through stdin.
Authorization calls the existing M22.4A `RemoteAuthorizer`; deletion takes only
`receipt_id` and calls the existing M22.4B `RemoteDeleter`. Control JSON is only
a strict canonical view of the already-validated Catalog authority.

## Process lifetime and distributed ambiguity

Raw stdout is never returned as bare `Popen.stdout`. A process-owning stream
waits and reaps at EOF and returns `b""` only after exit zero. Therefore exact
complete Raw bytes followed by exit 1/255 fail the existing M22.3 final EOF
gate. Premature close closes stdout, terminates, bounded-waits, kills if needed,
and reaps. Raw stderr is inherited rather than left as an unread pipe, so
pressure cannot deadlock stdout transfer.

`RemoteArchiveSession.run_one()` selects at most one source, creates one durable
receipt, reuses its exact bytes/ID for bounded authorization retry, and resolves
authorization or deletion response loss by inspecting the same receipt ID.
It never receives again, creates a replacement receipt, selects another source,
or deletes without validated pending authority. SSH exit zero alone is not
source, receipt, authorization, deletion, or recovery authority; SSH nonzero
after a command begins does not prove the durable semantic operation was
absent.
