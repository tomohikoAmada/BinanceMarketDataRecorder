## Diagnosis

The former incremental audit enumerated and scanned the manifest filesystem,
then opened the Catalog and compared all current chunk rows with that earlier
inventory. `AcceptanceObserver._raw_evidence` then performed another
current-Catalog membership comparison. During a long scan, ArchiveManager
could durably verify the external Raw and manifest, commit
`LOCAL_DELETE_PENDING`, unlink the internal sealed Raw, and later commit
`LOCAL_DELETED`. A later Catalog read could therefore be compared with stale
filesystem membership and report a false blocker. The same ordering could
also observe an internal Raw disappearance between `is_file()` and validation.

## Implementation

- `Catalog.chunks_in_states_snapshot()` captures all chunk lifecycle rows in
  one short-lived read transaction. The incremental audit records a compact
  row count and canonical digest before the long manifest scan.
- Membership comparison, continuation membership, new-chunk scanning, and
  absence classification use only that frozen boundary row set. Manifest or
  Catalog rows committed after the boundary are deferred to the next sample;
  they are not emitted as `catalog_manifest_disagreement` or
  `unexplained_raw_absence`.
- The independent later all-Catalog comparison was removed from
  `AcceptanceObserver`; it consumes the audit engine's single frozen result.
- Missing local Raw is classified with a fresh exact-chunk lifecycle read.
  Rows that were not already terminal at the boundary are accepted only for
  `LOCAL_DELETE_PENDING` or `LOCAL_DELETED` when the Catalog identity,
  retained internal manifest, registered target identity, external Raw, and
  external manifest pass the existing ArchiveManager verification. A row
  already `LOCAL_DELETED` at the boundary reuses the identity of that
  existing verified terminal transaction, keeping the large retired history
  bounded. Existing `REMOTE_DELETED` classification is retained.
  Pre-authorization states, absent or tampered external artifacts in the
  active verification path, malformed identity/manifest, and Catalog defects
  remain fail-closed.
- If Raw disappears during validation, the same fresh lifecycle path is used;
  present corrupt Raw still raises a strict audit failure. The observer's
  target-root resolver uses read-only Catalog/volume observation and creates no
  Catalog WAL/SHM or Recorder-tree mutation.

No Raw, external archive, Catalog, acceptance evidence, or exchange contract
was redesigned. Existing acceptance and continuation schema versions remain;
`catalog_boundary` and `raw_loss` are additive audit details.

## Regression evidence

The regression test was written before the production fix and run against the
old behavior without an intermediate commit. The command

```text
python3.12 -m pytest -q tests/integration/test_m22_9_acceptance.py::test_catalog_row_committed_after_inventory_boundary_is_deferred
```

failed as expected with the old implementation because the result contained
`catalog_manifest_disagreement:<chunk_id>` while the test required no Catalog
finding. After the fix, the boundary and archive-race tests pass.

Deterministic controls now cover:

- a post-boundary Catalog row, including a manifest published with that row,
  being deferred;
- a manifest published after a boundary whose chunk row was already ACTIVE,
  followed by inclusion and deep scan at the next boundary;
- evidence-chain resume while a post-boundary manifest is intentionally
  absent from the continuation membership;
- real ArchiveManager held after unlink / before the `LOCAL_DELETED` commit,
  with both already-missing and validation-time disappearance accepted only
  as `AUTHORIZED_LOCAL_DELETE`;
- unauthorized local absence in a pre-authorization state;
- tampered external Raw during `LOCAL_DELETE_PENDING`;
- observer read-only behavior: Catalog sidecar bytes and every file under the
  Recorder fixture tree are unchanged.
