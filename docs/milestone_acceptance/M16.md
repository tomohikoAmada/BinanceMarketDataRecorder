## Architecture decisions

Consumers configure one Recorder application-data root and select one exact
content-addressed build. There is no inferred or mutable “latest” build.
Manifest resolution remains internal to the public replay package; physical Raw
archive location is never a consumer concern.

`replay-order.v1` uses stable logical provenance after the chosen event clock.
Exchange order adds receive UTC before market/source tie-breaks. Monotonic time
appears only after Collector identity, so it is not treated as a cross-process
clock. Streams without documented exchange time are not assigned invented
values.

Replay remains read-only and uses ephemeral temporary work rather than
Recorder persistent storage. The API owns no strategy, factor, backtest,
account, position, order or trading behavior.

## Known limitations

Replay scans and verifies the complete selected build even for a narrow query,
favoring build integrity over partial availability. It has no mutable latest
pointer, build chronology or server/API gateway; callers explicitly configure
the root and build ID.

External merge memory and open descriptors are bounded, but temporary disk can
approach the selected logical row volume. The consumer process must have
writable ephemeral temporary space. A process crash may leave operating-system
temporary files for normal OS cleanup; no persistent Recorder artifact is
created.

Exchange-time replay necessarily rejects, omits or explicitly falls back for
streams without a documented exchange clock. Checkpoint seek accelerates only
single-market/symbol diff depth, not arbitrary multi-stream replay. Complex M15
JSON text fields remain JSON rather than nested Arrow objects.

## Data compatibility and rollback

M16 does not change EventEnvelope, Raw framing/payloads/manifests, normalized
Parquet bytes or manifests, archive state/protocol, Catalog schema, M6
checkpoint bytes, Collector/service behavior or daily metrics. It adds a
read-only Python API, documentation, example and package typing marker.

Rollback removes the M16 package/example/contracts and restores the prior
package metadata while retaining every M15 dataset, Raw artifact, manifest,
Catalog record and checkpoint. Consumers requiring `replay-order.v1` pin the
matching distribution or retain an exported replay with build/query/version
provenance. Rollback never rewrites source data.
