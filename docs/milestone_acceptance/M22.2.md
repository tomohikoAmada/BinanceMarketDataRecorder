The implementation uses `archive_set_id` as logical collection identity and
the existing `storage_id`, volume UUID, registered relative path, and marker
nonce as physical identity. The existing `registered-storage.v1` marker is
revalidated before every Archive Set metadata write and is never rewritten.

## Media-local authority

The medium-local identity is
`.binance-market-data-recorder-archive-set.json` with schema
`archive-set-medium.v1` and exactly these fields:

```text
schema
archive_set_id
storage_id
volume_uuid
registered_relative_path
marker_nonce
```

Inventory records use `archive-set-entry.v1` at
`archive-set/entries/<chunk-id>.json`. Each immutable entry binds one whole
chunk to one physical medium, artifact path, archive manifest identity, and
Raw stored identity. There is no segment, stripe, shard, or replica model.
Conflicting existing metadata, unsafe paths, malformed data, set/storage
disagreement, and cross-media chunk collisions fail closed.

## Workspace index and read-only boundary

`ArchiveSetIndex` uses only an explicit caller-supplied SQLite path and stores
set, physical-media, and artifact discovery rows. It is convenience state, not
authority. Rebuild scans supplied media-local metadata transactionally from
zero, supports an attached subset of a set, and does not write to media. A
medium remains independently interpretable when other media or the workspace
index are absent. Archive Set is not Backup: no replication, RAID, striping,
receipt, transfer, or deletion authorization is implemented.

The live Recorder Catalog, `ChunkState`, `ArchiveState`, storage marker,
ArchiveManager, RemoteSourceExporter, Raw schema, and existing external
archive manifest schema are unchanged. M22.3 remains **NOT STARTED**.
