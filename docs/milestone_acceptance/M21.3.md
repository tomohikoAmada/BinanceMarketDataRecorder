## Repair scope

### USD-M capture sessions

- A session stop before the first snapshot is normal retirement, not a
  `SnapshotUnavailableError`.
- Global stop, cancellation, disconnect, planned rotation, server shutdown, and
  outer resync retain distinct existing control signals.
- A blocking snapshot that finishes after session retirement is awaited but not
  applied to the retired stream generation.
- Task cancellation shields the non-cancellable SDK worker, awaits it to
  completion, retrieves its outcome, and then re-propagates `CancelledError`;
  no snapshot worker is abandoned.
- HTTP 418/429 honor an available safe retry boundary and otherwise use the
  existing bounded snapshot backoff; HTTP 5xx uses that bounded backoff. Both
  waits remain session-stop interruptible and non-terminal.
- Permanent HTTP responses, missing snapshot identity, invalid model/schema,
  and parsing failures use stable typed response exceptions and remain fatal.
- Existing transient SDK/runtime retry behavior remains bounded.
- A session that ends without global stop or a resync request remains terminal.
- Resync still marks the interval untrusted. READY still requires a fresh
  snapshot plus correct buffered diff bridging.

### Archive-aware sealed recovery

| Current chunk state | Recovery behavior |
|---|---|
| no Catalog row | Verify Raw manifest/artifact, register, and move through the existing sealing contract |
| `ACTIVE`, `RECOVERED` | Verify, then atomically progress to `SEALING` |
| `SEALING` | Verify, then atomically progress to `SEALED` |
| `SEALED` | Verify immutable Catalog/manifest identity and leave unchanged |
| `ARCHIVE_COPYING` | Verify manifest, Catalog, and Archive transaction identity; preserve |
| `ARCHIVE_VERIFYING` | Verify identity; preserve |
| `ARCHIVED_VERIFIED` | Verify identity; preserve |
| `LOCAL_DELETE_PENDING` | Verify metadata identity without requiring Raw; preserve |
| `LOCAL_DELETED` | Verify metadata identity; never recreate Raw; preserve |
| `QUARANTINED` | Fail closed; never promote |

Archive transaction state must agree with the mapped chunk state. Source
manifest SHA-256, source paths, chunk, market, stream, stored size, and stored
SHA-256 must agree. Contradictions raise `RecoveryConflictError` with a stable,
redacted error type. Recovery doesn't create Archive transactions, copy or
delete files, rewrite external manifests, or hold a database transaction while
hashing files.

## Deterministic regressions

Offline tests cover:

- pre-snapshot session stop and global stop;
- `unexpected_disconnect`, `planned_rotation`, `server_shutdown`, and outer
  resync session retirement;
- snapshot completion after retirement;
- cancellation while the SDK worker is active;
- real snapshot task exceptions, transient 418/429/5xx retry, permanent HTTP
  and invalid model/schema propagation, and Spot parity;
- 100 consecutive resync sessions with no pending Task or unhandled
  `ExceptionGroup`;
- repeated `SEALED` reconciliation idempotency;
- all five Archive lifecycle preservation states;
- Catalog/manifest and Archive transaction identity conflicts;
- no duplicate Archive transaction, external manifest rewrite, or Raw revival;
- a deterministic post-`SEALED` Archive reservation interleaving;
- one Recorder recovery process plus one Archive writer process against a real
  temporary WAL Catalog, including unique transactions and
  `PRAGMA integrity_check=ok`.

All test storage is under pytest temporary directories. Tests don't access the
production data root, Binance, Mihomo, the Internet, or the registered 4 TB
production Archive tree.

## `recv_messages` conclusion

The AttributeError originates in the third-party `websockets` asyncio callback
path, not project code or an adapter. The current evidence doesn't establish a
compatible fixed release, and the next major release retains the relevant
unguarded access. Dependencies and lock state are unchanged. This remains a
separate known risk with a local-proxy reproduction plan.
