`binance-sdk-derivatives-trading-usds-futures==14.0.0`, and
`websockets==15.0.1`. Generated SDK internals and the generic WebSocket API are
exact-pinned because they are the subject of the capability decision. Pydantic
keeps its compatible-major range. Development dependencies remain separate.
No deprecated Futures connector, third-party `python-binance`, Binance MCP,
FastAPI, GUI, database, Parquet, or machine-learning package was added.

## Excluded scope and known limitations

M2 adds no production Collector, long-running connection, WebSocket endpoint
adapter, Raw writer, Catalog, archive, storage service, GUI, account/credential,
strategy, backtest, or trading implementation. The online test is deliberately
opt-in and short-lived.

Some interactive developer-portal catalog pages return a CloudFront/WAF HTTP
202 challenge to scripted clients. The updater fails closed and selects
downloadable official Markdown plus official SDK source; no unofficial mirror
is used. M4/M5 must revalidate exact live stream routing and schemas. Official
SDK REST models do not retain the byte-exact HTTP response body, so later
snapshot provenance cannot claim it.

## Compatibility and rollback

There is no market-data compatibility impact: no Raw, Catalog, Manifest,
normalized, or Replay data exists. Package runtime dependencies and the
transport decisions are new engineering contracts only. Rollback is a revert
of the single M2 commit; no production state requires migration. Replacing
either transport requires a superseding ADR and equivalent evidence.
