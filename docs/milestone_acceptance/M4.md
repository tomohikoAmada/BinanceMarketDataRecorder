## Architecture decisions

- Separate raw endpoints were chosen instead of a combined stream. Static
  endpoint identity lets malformed messages be retained under the correct
  stream and avoids silently stripping a combined wrapper.
- Network receipt, schema extraction, and disk persistence are separate stages.
  Socket receipt never compresses, writes Parquet, reconstructs a book, or
  blocks on filesystem I/O.
- The existing shared Catalog connection is now protected by a reentrant lock
  and allows checked cross-thread use, because M4 persistence runs off the
  asyncio receive loop. Market events still never enter SQLite.
- Spot-specific code is isolated below `binance.spot`; no USD-M behavior or
  speculative multi-exchange abstraction is added.

## Excluded scope and known limitations

M4 contains no USD-M Collector, order-book reconstruction, continuity/gap
classification, normalization/Parquet, archive manager, daily metrics,
launchd service control, blue-green overlap, GUI, account/credential handling,
strategy, backtest, or trading code. `status` therefore does not invent a
running Collector state.

The 15-minute public smoke validates current routing and sustained receipt but
cannot naturally force a 24-hour disconnect or serverShutdown; deterministic
local protocol/fault tests cover those paths. M6 owns order-book correctness,
gap detection, resync, and bookTicker comparison. M8 owns durable reconnect and
quality counters. M13 owns overlap that avoids planned-rotation gaps.

The SDK provides a parsed REST model rather than exact response body bytes. The
snapshot provenance states this limitation and does not claim byte-exact HTTP
retention. Only an allowlist of public diagnostic/rate-limit response headers is
stored.

## Data compatibility and rollback

M4 does not change `event-envelope.v1`, `raw-chunk.v1`, or the manifest schema.
It begins producing those M3-compatible artifacts with stream names
`diff_depth`, `agg_trade`, `book_ticker`, and `depth_snapshot`. Spot WebSocket
payload bytes are exact. Snapshot bytes are a declared deterministic provenance
document, not a claimed HTTP body.

Rollback stops the Spot worker, drains and seals accepted records, and reverts
the single M4 commit. Existing M4 Raw chunks remain readable by the M3 reader
and must not be rewritten or deleted. Any capture interval after stopping is an
explicit operational gap, not silently complete data.
