## Architecture decisions

- ADR-0013 freezes aggregation, idempotency, histogram, rollover, atomic output
  and unavailable-value semantics.
- SQLite stores aggregate batches rather than one row per market event. Raw
  bytes, prices, quantities and source sequences remain only in Raw.
- The first record metric includes the chunk header so summed
  `raw_bytes_written` reconciles to the uncompressed chunk size.
- SDK REST response wire bytes are `null/UNAVAILABLE_SDK_RAW_BODY`; parsed model
  length is never mislabeled as network traffic.
- M9/M10/M15-owned fields are present with `UNAVAILABLE_UNTIL_M9` or
  `NOT_IMPLEMENTED`, never fabricated zeroes.
- `status` remains `NOT_RUNNING` until a supervised service exists, even if an
  unvalidated file claims otherwise.

## Excluded scope and known limitations

M8 does not implement M9 external-volume capacity, M10 archive transactions,
M11 forecasting, M14 supervised service/launchd state, M15 normalization,
GUI/web, accounts, credentials, strategies, backtests or trading.

CPU/RSS/free-space samples are periodic and a very short stream can report
`INSUFFICIENT_DATA`. Histogram percentiles are deterministic bucket upper
bounds, not exact stored samples. A kill before an in-memory batch commits can
lose operational counters while Raw remains recoverable; automated Raw/manifest
reconciliation and the kill matrix remain M17 work. The M6 quality observer is
an explicit library boundary because continuous order-book service assembly is
not yet implemented.

## Data compatibility and rollback

M8 does not change `event-envelope.v1`, `raw-chunk.v1`, Raw manifests, stream
schemas, M6 order books or M7 side-data provenance. It additively creates the
Catalog `metric_batches` table, `operational-metric-aggregate.v1`,
`daily-operational-report.v1`, and derived JSON/CSV report files.

Rollback stops report generation and reverts M8 while preserving Raw and
manifests. The additive table/reports may be retained, ignored or regenerated;
they never authorize Raw deletion.
