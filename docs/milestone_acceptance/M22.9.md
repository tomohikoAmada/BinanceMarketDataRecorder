## Confirmed production defect

Eight Recorder exits shared the fatal chain
`IngressBackpressureTimeout -> IngressPostCloseHandoffTimeout ->
CoreMarketTerminalFailure`; five were USD-M `book_ticker`, one was Spot
`book_ticker`, and two additional USD-M `book_ticker` exits occurred during
the intended formal window.

The queue and fail-fast policies behaved as designed. The correctness defect
was the USD-M fatal post-close branch: after the received boundary frame failed
to enter the bounded writer handoff, `IngressPostCloseHandoffTimeout` escaped
while `UsdMStreamCollector.run()` still held `outcome="stopped"`. Its `finally`
block consequently built no reconnect seal intent, wrote no
`STREAM_DISCONTINUITY_STARTED`, applied no `reconnect_gap`, and allowed the
writer to seal the preceding Raw tail with ordinary completeness semantics
before the exception reached core supervision.

The boundary frame had been received from the WebSocket but was not admitted
to the writer queue and was not persisted. Its SHA-256 may be retained as
forensic boundary identity, but `boundary_frame_persisted=false`; the payload
is never inserted into Raw and never receives a fabricated EventEnvelope.

Spot contains the corresponding fatal-boundary guard at this authority. Its
previous test stopped after checking one incomplete manifest and STARTED row;
the correction strengthens Spot coverage through fresh startup recovery,
authentic first-new Raw sync, same-gap COMPLETED, and no payload fabrication.
USD-M now follows the same already-authoritative ADR-0027 ordering.

## Correction

On an USD-M post-close handoff timeout the collector now:

1. retains the exact in-memory boundary identity and payload digest;
2. records that the handoff failed and remembers the closing connection;
3. classifies the fatal path as `ingress_backpressure` before writer release;
4. builds one versioned reconnect seal intent with
   `boundary_frame_persisted=false` and the exact gap identity;
5. durably writes STARTED before ordinary old-tail sealing, or preserves the
   same intent through the existing SEALING fallback if STARTED itself fails;
6. forces manifest-only `reconnect_gap`, so the old tail is
   `gap=true`/`complete=false` without mutating Raw bytes;
7. re-raises `IngressPostCloseHandoffTimeout`, preserving fail-fast core and
   systemd restart semantics.

Startup recovery remains the existing R1/R2/R2.1/R2.2 implementation. It
restores the same open `gap_id`; the first authentic replacement frame alone
receives `sequence_gap`; Raw sync precedes one exact COMPLETED event with
`historical_continuity_restored=false`.

No queue capacity, queue boundedness, saturation budget, post-close timeout,
Raw format, Catalog schema, reconnect reason taxonomy, or restart policy
changed.
