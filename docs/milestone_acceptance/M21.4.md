## Repair scope

- Replace USD-M WebSocket receipt `put_nowait` failure with bounded,
  Writer-aware, stop-aware awaitable backpressure.
- Close a continuously saturated connection at a finite deadline and give the
  already-received boundary frame a separate bounded post-close queue handoff.
  Raw drain/fsync/seal then safely follows the underlying I/O without a false
  five-second end-to-end persistence claim.
- Drain/seal before opening a new generation; never mix the old and new
  overload generations in one Raw chunk.
- Persist the existing `sequence_gap` flag on both the last-old boundary and
  first recovered Raw event, explicitly sync the first-new marker, and only
  then commit internal discontinuity completion evidence. Recover a unique
  unmatched STARTED record across process restart; conflicting unmatched gaps
  fail closed. Both sides remain conservatively incomplete.
- Recover `book_ticker` and `agg_trade` at stream scope without restarting the
  Recorder; historical completeness remains false.
- Force `diff_depth` through UNTRUSTED, fresh Snapshot, and correct `U/u/pu`
  bridging before READY.
- Preserve process-level fail-closed behavior for boundary-persistence,
  append, drain, fsync, seal, Catalog, and unexpected Writer failures.
- Add transition-only queue/Writer latency and generation diagnostics without
  changing formal soak or public schemas.

## M21.4.1 blocking-review correction

PR #7 review comment 5173209447 identified that a nonzero Raw durability
interval allowed Catalog completion to become durable before the first-new Raw
marker, and that an unmatched STARTED record was held only in process memory.
The correction preserves this strict order:

1. append and drain the first-new `sequence_gap` envelope;
2. explicitly `StreamSpool.sync()` that Raw marker;
3. commit `STREAM_DISCONTINUITY_COMPLETED` with SQLite `synchronous=FULL`;
4. only then notify the envelope observer/readiness path and clear recovery
   state.

Sync or Catalog failure leaves STARTED unmatched, propagates the original
exception, and remains Writer/Collector fatal. At construction, every USD-M
stream queries the existing operational-events table for its unmatched STARTED
records. Exactly one restores the same gap ID, original connection, and
original generation; the first accepted event in the replacement generation
gets one `sequence_gap` marker. Multiple unmatched records raise stable
`IngressGapStateConflict` without selecting one or writing new evidence. A
matched STARTED/COMPLETED pair starts normally without adding another marker.
No Catalog, Raw, Manifest, or public schema changed; only a read-only Catalog
query was added.

Deterministic tests use `durability_interval_seconds=0.75` and cover ordering,
sync failure, reconstructed Collector state, same-gap completion for
`book_ticker` and `agg_trade`, exactly-once marker placement within the resumed
generation, conflict refusal, already-completed startup, and cancellation after
Raw sync but before Catalog submission. The correction's local gates are:

- focused Gap/backpressure tests: `32 passed`;
- USD-M/Spot/Supervisor/Recovery/Archive expansion: `147 passed`;
- 1000 reconnect/rotation plus 100 overflow cycles: `2 passed`;
- million-event Raw stress: `1 passed in 195.94s`;

## M21.4.2 blocking-review correction

PR #7 review comment 5173445886 identified that cancellation of an asyncio
Task awaiting `asyncio.to_thread(...)` does not stop a blocking Raw or SQLite
operation already running in its worker thread. Cleanup could therefore race
`StreamSpool.sync()` or seal with `abort_writer()`, or race a discontinuity
Catalog write with `Catalog.close()`.

USD-M mutating blocking calls now have one explicit asyncio owner. The owner
creates a Task for the thread call and awaits it through `asyncio.shield`. If
the caller is cancelled, including repeatedly, it retains ownership and waits
for the worker to finish before retrieving the worker result and allowing
abort, close, or cancellation propagation. If the worker succeeds, the
original cancellation is propagated. If storage I/O fails at the same time,
the original storage exception takes priority and chains the cancellation so
the integrity failure remains fail-closed. No exception is suppressed.

This ownership covers Raw drain, explicit gap-marker sync, final seal, Writer
abort, and both STARTED and COMPLETED operational-event writes. Deterministic
tests block inside real worker-thread calls and prove that the asyncio owner
cannot finish, `abort_writer()` cannot enter, and `Catalog.close()` cannot run
until the operation is released. Success and injected-failure paths cover Raw
sync and both Catalog event types; adjacent drain/seal cancellation and 100
alternating sync/Catalog/seal/normal-stop races check Task, exception, FD,
thread, Catalog, and recoverable-Raw state.

Cancellation still cannot impose a deadline on an OS write, fsync,
compression, or SQLite call already executing. A permanently hung kernel I/O
operation therefore remains a known risk: the owner waits rather than closing
a descriptor or connection out from under the worker. The M21.4.1 order remains
unchanged: first-new marker append/drain, Raw sync, Catalog COMPLETED, observer,
then recovery-state clearing. No Raw, Manifest, Catalog, or public schema
changed, and this correction remains USD-M-only.
