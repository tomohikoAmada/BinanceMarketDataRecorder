## Architecture decisions

- The current official route split is mandatory: high-frequency depth and
  bookTicker use `/public`; aggregate trades use `/market`. Legacy unrouted
  Market streams were not used.
- Separate raw endpoints preserve stream identity even for malformed payloads
  and avoid combined-wrapper transformation.
- USD-M is isolated below `binance.usdm`; its `pu` field is not added to Spot.
  No speculative other-exchange abstraction was introduced.
- USD-M reuses the accepted M3 writer and M4 lifecycle pattern. It performs no
  compression, Parquet conversion, order-book work, or complex computation on
  the socket receive boundary.

## Excluded scope and known limitations

M5 contains no order-book reconstruction, gap/resync classification, mark
price, funding, open interest, liquidation, exchange-info workers, daily
metrics, normalization/Parquet, archive operations, launchd service, account
API, credentials, trading, GUI, strategy, factor, or backtest code.

The live gate proves current routes and simultaneous receipt but cannot
naturally force every network fault or the 24-hour connection limit; local
deterministic tests cover Ping/Pong, disconnect/reconnect, and lifecycle
boundaries. M6 will decide whether `pu` continuity is satisfied and will mark
gaps/resync intervals. M8 owns durable daily and reconnect statistics; M13
owns overlap-based planned rotation.

The official SDK supplies a parsed REST response model, not exact original
HTTP response bytes. The snapshot provenance states this limitation. A
successful 30-minute run is operational evidence, not a guarantee that public
Binance access will always be available from this host.

## Data compatibility and rollback

M5 does not change `event-envelope.v1`, `raw-chunk.v1`, or the manifest schema.
It adds M3-compatible `market=um_perpetual` artifacts with stream names
`diff_depth`, `agg_trade`, `book_ticker`, and `depth_snapshot`. WebSocket
payload bytes are exact; snapshots are declared deterministic provenance
documents. Existing Spot artifacts remain unchanged and readable.

Rollback stops only the USD-M worker, drains and seals accepted USD-M records,
marks any resulting capture gap operationally, and reverts the single M5
commit. Spot continues under its independent failure domain. Existing USD-M
Raw chunks remain readable and must not be rewritten or deleted.
