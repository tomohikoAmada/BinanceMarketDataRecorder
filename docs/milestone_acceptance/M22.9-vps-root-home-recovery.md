## Incident and cause

An administrative cleanup intended for a bounded disposable workspace was
constructed across local and remote shell-expansion boundaries. The remote
variable used in the target was unset; the resulting command addressed
`/root/` rather than the intended child. The command recursively removed the
contents of the VPS root user's home directory, including
`/root/.ssh/authorized_keys`, and subsequent SSH sessions failed with
`Permission denied (publickey)`.

The exact initiating command and expansion failure are preserved in the
operator/agent conversation record. No shell audit or history survived under
`/root`, so this document does not claim a server-side command-history proof.
Post-incident inspection proves only the resulting empty/recreated root-home
state and the unaffected authorities listed below.

## Permanent command-safety rule

Remote administrative cleanup is fail-closed from this milestone onward:

1. Do not issue recursive removal against `/root`, any home directory,
   `/`, `/etc`, `/opt`, `/var`, `/srv`, a mount root, or an unresolved value.
2. Do not interpolate a local variable into a remote cleanup expression or
   assume a variable survives the SSH boundary.
3. Prefer retaining evidence and disposable workspaces. If cleanup is truly
   required, create the workspace with `mktemp -d` under an explicitly allowed
   disposable parent and clean only the exact returned child.
4. In the same remote shell, enable unset-variable failure, require a nonempty
   value, canonicalize it, verify its parent/prefix and that it is neither the
   parent nor a protected path, and print the resolved target before mutation.
5. Separate target creation, read-only inspection, and cleanup into distinct
   reviewed steps. Never combine operational work and recursive cleanup in one
   opaque SSH string. Cleanup failure is normally nonfatal; broadening the
   target is forbidden.
6. Do not use recursive deletion merely to obtain a clean workspace. A fresh
   unique directory is the default.

These rules apply to humans, agents, prompts, scripts, local-to-VPS commands,
and future automation.
