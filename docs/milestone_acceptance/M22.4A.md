# M22.4A Acceptance — Remote deletion persistence / Catalog compatibility / recovery model

## Result

M22.4A corrections are **IMPLEMENTED** on the dedicated feature branch. This
record covers the non-destructive remote pre-delete authority and read-only
recovery model only. It does not claim merge, deployment, production
readiness, source deletion, or M22.4B completion. The four focused review
corrections are implemented; this record awaits independent focused closure
review.

## Additive same-Catalog authority

The existing Catalog SQLite database now contains exactly two additive remote
tables: `remote_archive_transactions` and `remote_archive_events`. The current
authority row is keyed by `receipt_id`, uniquely owns `chunk_id`, stores the
exact canonical M22.3 receipt bytes as a BLOB, and binds the extracted source,
Archive Set, storage, artifact, session, verification, and timestamp facts.
The append-only event row records exactly one initial
`NULL -> REMOTE_DELETE_PENDING` event with
`remote-authorize:<receipt_id>` idempotency.

`RemoteArchiveState` is separate from physical chunk and same-host archive
state. During both remote states `chunks.state` remains `SEALED`. No
`ChunkState`, `ArchiveState`, `ARCHIVE_CHUNK_STATES`, `ARCHIVE_TRANSITIONS`,
same-host row schema, or same-host transition meaning changed.

Writable initialization inspects `sqlite_master`. Both remote tables absent is
the legitimate pre-M22 case: both tables and indexes are created and validated
inside one explicit transaction. Both present is validated through table,
column, primary-key, unique-index, foreign-key, named-index, state-check, and
timestamp-invariant evidence. One present or any malformed authority schema
fails closed. Read-only open performs no DDL; legitimate absence is an empty
remote projection, including legacy-safe remote-aware queries and no new
sidecar/directory entry.

## Receipt/source binding and authorization boundary

`RemoteArchiveReceipt.from_bytes()` remains the only parser. Authorization
re-runs M22.1-strength source validation, requires the exact caller selection,
compares every receipt source field, and persists only after `BEGIN IMMEDIATE`
rechecks `SEALED`, no same-host owner, no conflicting remote owner, and
unchanged Catalog source identity. The commit is the durable VPS pre-delete
boundary. Exact retry returns the existing row without rewriting its receipt,
identity, or creation time; another receipt/session for the chunk and receipt
replay against another chunk fail closed.

Every remote row used for selection, backlog/counting, or reporting reparses
exact receipt bytes, recomputes `receipt_id`, checks extracted columns, path
canonicality, state/timestamp invariant, the initial event's own `receipt_id`,
and current Catalog source identity. Descriptor-derived reporting fields also
read the exact retained source manifest, reconstruct the complete M22.1
descriptor with `canonical_descriptor_bytes()`, and require its digest to equal
both the row and receipt binding. Raw is additionally fully validated where
source authorization/deletion safety requires it, but not for historical
reporting.

Same-host reservation now checks any remote owner inside its existing
`BEGIN IMMEDIATE`, including its idempotent-existing branch. Remote
authorization checks any same-host owner inside its own `BEGIN IMMEDIATE`.
Independent SQLite connections prove remote-first, same-host-first, and
simultaneous acquisition produce exactly one owner with no external lock.

## Recovery and consumer projection

The pure/read-only decision model exposes NORMAL, CASE A, CASE B, CASE C,
CASE D, TERMINAL_ABSENT, TERMINAL_PRESENT_CONTRADICTION, and
IMPOSSIBLE_SAME_HOST_REMOTE_OVERLAP. Source observation separately reports
PRESENT_MATCHING, PRESENT_MISMATCH, ABSENT, and UNKNOWN. ABSENT requires the
exact Raw leaf to be missing below a safely observed exact parent; permission,
I/O, stale/unstable, unsafe-parent, and nonregular-object cases never become
absence.

Remote pending/deleted rows are excluded from ordinary M10 archive selection,
remote source export selection, archive backlog, oldest-unarchived forecast,
and threshold inputs only after remote authority validation. Pending retained
Raw files/bytes remain separately visible in Catalog aggregate, manager/status,
service status, and CLI output. Daily reporting accounts the locally archived
file/bytes on remote authorization UTC day only after revalidating persisted
market/stream against the retained descriptor, without inventing an
`ArchiveState`. Spool reconciliation preserves CASE A and fails closed on
contradictory terminal/overlap evidence.

## Explicitly not implemented

- source unlink, remove, delete-rename, or manifest deletion;
- deletion-parent filesystem durability;
- any callable production transition to `REMOTE_DELETED`;
- SSH or `RemoteTransport`;
- post-session Catalog snapshots (M22.6);
- M22.4B.

The schema accepts test-only `REMOTE_DELETED` fixture rows so M22.4B needs no
schema redesign. Production M22.4A can create only `REMOTE_DELETE_PENDING`.
Rollback to a pre-M22 binary after any remote row persists is **NOT CLAIMED /
NOT GENERALLY SUPPORTED**; no downgrade migration or fake local state exists.
