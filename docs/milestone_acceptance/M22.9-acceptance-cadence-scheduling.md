# M22.9 Acceptance Observer Cadence Scheduling Fix

Date: 2026-09-14

## Decision

The acceptance stage runner now schedules regular observations from the
monotonic/BOOTTIME sample-start cadence. Observation work consumes the
`SAMPLE_INTERVAL_NS` budget; the runner no longer adds a fixed five-minute
sleep after each completed observation.

This is an offline implementation and review candidate only. It does not
authorize deployment, Recorder start, Binance traffic, a new T0, or Formal
qualification. The prior live `acceptance_observation_gap` result remains
unchanged and receives zero Formal credit.

## Production delta

`src/binance_market_data_recorder/cli.py` now uses the existing observer
clock's BOOTTIME value before each regular sample. The next target is the
actual sample start plus `SAMPLE_INTERVAL_NS`. The wait is zero when the
observation has overrun the target, and is capped by the remaining stage
duration. An overrun re-anchors the following target from the immediately
started sample, so missed slots are not replayed.

The first regular sample keeps the existing immediate-start behavior. A valid
resume with an existing sample starts from that sample's BOOTTIME authority
plus one interval. SIGINT/`KeyboardInterrupt` handling remains in the
foreground CLI path.

No change was made to `MAX_EVIDENCE_GAP_NS`, `STAGE_DURATION_NS`, evidence
timestamps, hash chaining, resume admission, finalization, verifier behavior,
the v2 evidence schema, Catalog, manifests, Raw, ArchiveManager, Recorder, or
the systemd transient-unit procedure.
