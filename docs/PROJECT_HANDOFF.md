## Active Engineering Direction (2026-11-02)

The previous P0–P6 milestone plan has been **abolished** and replaced by the finalized Python milestone plan (`M1` → `M2` → `M3` → `M4`) in [`production_milestone_plan.md`](production_milestone_plan.md):

1. **M1 — Primary Performance, I/O & Source Amplification Remediation**:
   - **M1.0**: Freeze a deterministic multi-stream replay baseline fixture on current `main` (`f109ffc`) before changing runtime code (**COMPLETED after independent correction**; see [`benchmarks/m1.0-review-20261102.md`](benchmarks/m1.0-review-20261102.md)). Corrected v2 reports in `docs/benchmarks/baseline-main.json` and `baseline-main.json` match; two runs each decoded 13,966 Raw frames with identical content digest `cb65e4c7...`. At the M1.0 freeze, production `src/` matched `f109ffc`; M1.1 subsequently changed rotation defaults. The 12s synthetic baseline does not establish steady-state rotation rates or backlog growth.
   - **M1.1**: **COMPLETED after independent validation**: default `900s / 128 MiB`, existing phase staggering, independent `1s fsync`; actual file/seal/archive-reservation counts decreased 91.28% including shutdown in a logical-clock replay. Real 128 MiB seal/receipt-queue and SIGKILL recovery passed. See [review and measurement boundaries](benchmarks/m1.1-review-20261102.md).
   - **M1.2**: Coalesce unsaved healthy `AvailabilityJournal` checkpoints per source and replace 10s per-source SQLite row churn with per-source transitions + a shared monitor watermark. Switch routine `Catalog` WAL commits to `PRAGMA synchronous = NORMAL` while enforcing a `FULL` / `wal_checkpoint(TRUNCATE)` barrier before irreversible local source deletion (`LOCAL_DELETED`), plus startup WAL rollback reconciliation (`ADR-0059`).
   - **M1.3**: Retire completed one-shot REST seeds (`kline_seed_*`, `continuous_seed_*`, `reference_price_seed`) from active polling/monitoring loops; directly disable the 10 overlapping `S12` intervals (`1s`–`4h`, `8h`) covered by `S11`, without a separate equivalence script; persist closed WS K-line bars (`k.x == True`) with in-memory liveness updates, `forming_filtered_count` accounting, and automatic REST backfill (`closed_bar_backfill`) on missed close boundaries (`ADR-0058`).
   - **M1.4**: **COMPLETED after independent correction** ([review](benchmarks/m1.4-review-20261102.md)): directly encode `EventEnvelope` and accumulate stats without residual Writer dictionary copies; preserve Raw v1, single REST provenance serialization and batched persistence; fix unobserved Future exceptions on drain failure. No VPS deployment was performed.
2. **M2 — De-Overengineering, Verification Consolidation & Codebase Decoupling**:
   - **M2.1**: **COMPLETED after independent correction** ([review](benchmarks/m2.1-review-20261102.md)): live sealing has zero compressed-file readback, and the capture runtime no longer creates a verification worker or exposes a live-verification toggle. Simplified compression results, removed test-compatibility fallbacks, and fixed compressed short writes. Crash recovery, archive validation and manual `verify-raw` remain available; use `--chunk-id` to recheck an already verified chunk. Next task: **M2.2**.
   - **M2.2**: Remove startup 0-record `.zst` chunks and extra boundary files; record one Catalog startup event and `process_boundary_before_first_frame` on each stream's first real chunk manifest.
   - **M2.3**: Extract a market-agnostic `PublicWebSocketStream` transport, map legacy `spot_symbols` / `usdm_symbols` configs onto the unified capture supervisor, and retire the duplicate legacy collector path after equivalence verification.
   - **M2.4**: Make `cli.py` imports command-scoped/lazy (isolating `pyarrow`, retired V1–V5 acceptance tools, `storage/macos/`, and `archive/remote_*.py` from the capture daemon) and split `storage/catalog.py` into domain modules.
3. **M3 — Controlled Three-Way Benchmark & Pre-VPS Convergence**:
   - Compare (1) Baseline `main`, (2) Optimized Same-Scope, and (3) Optimized Production-Scope over multi-rotation (`>= 45–60m`) runs, plus the 1M-event stress test and WAL rollback / K-line backfill regressions.
4. **M4 — GreenCloud VPS Continuous Qualification (`BTC + ETH`: `2h` → `12h` → `24h`)**:
   - Run `[recorder.coverage].underlying_assets = ["BTC", "ETH"]` on `greencloud-tokyo-01` in one continuous service incarnation across `2h`, `12h`, and `24h` checkpoints (any checkpoint failure requires fixing and restarting from `0h`).
