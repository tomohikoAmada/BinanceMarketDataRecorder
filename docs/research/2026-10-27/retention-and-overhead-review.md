# 信息保留、资源取舍与可借鉴实现

日期：2026-10-27。范围：Recorder当前计划、存储表示、本地代码及下列一手资料。运行时代码为P1的src tree `0a173540835c6eb78de26eab9d06d165cc4902aa`（读取时HEAD `5218d9d`）。这是静态检查及设计研究，不是下列候选的性能实测；没有生产操作，也没有修改运行时代码。P1运行时复审另见[审查记录](../../milestones/P1/review-20261027.md)。

用户最新方向：研究用途尚未确定，采集应与研究消费解耦；尽可能保留不同的信息，资源有限时优先重要信息。已授权把以下方向写入计划：[单份REST主体、明确资源优先级、去除无用途哈希和重复流程](../../adr/0053-single-rest-representation-and-required-information.md)。价格和数量精度、交易所时间、真实接收时间、产品身份、必要序列和缺口信息仍需保留。

下面区分观察细节的取舍与等价重复工作。前者必须说明少记录了什么；后者按同输入、同结果测收益。信息优先级是结合本项目约束提出的工程判断，不是假定某个策略会用哪些数据，也不是论文证明的通用排名。具体格式和资源配置在P2 / P3实现，本次不改写历史数据。

## 1. 每种 K 线都保留形成过程

[覆盖表 S11/S12、D21–D23 及共用边界](../../milestones/P0/coverage.md)要求展开各市场支持的 interval，保存未收盘更新，并区分 UTC / +08:00、连续合约、标记价 / 指数价等。这不是同一条消息的两份编码，而是数量可观的不同观测；订阅数会随产品、周期、价格类型和时区组合扩大。

虚拟货币可以全天交易，但一根1分钟K线仍有起止时间。例如12:00:00到12:00:59这一根，在12:00:10、12:00:20看到的成交量和最新价还会改变，到这一分钟结束才得到最终值。“未收盘更新”就是反复记录这一根还在形成的K线，和整个市场休市没有关系；官方字段`x`区分是否结束，来源已记录在[Binance资料索引](../../binance_sources.md)。

不再建议等待某个研究用途来决定保留范围。完整目标先保留；资源不足时，部分长周期的反复中间状态优先于独有逐笔 / 盘口事实成为缩减候选。代价是失去交易所当时发布的值和本机看到它的时点。官方最终值、不同日界 / 价格类型 / 连续合约仍有独立语义，离线聚合不自动等价。P2比较实际流量、压缩后字节和CPU，再写出受限配置；不承诺未测量的节省比例。

## 2. 每秒轮询最近成交时，整份列表可能高度重叠

[D06](../../milestones/P0/coverage.md)目前规划每秒有界查询最近成交列表，并明确 Raw 保存每次响应。同一成交可能在多次响应中反复出现；重叠多少取决于成交速率、返回条数和轮询时刻，不能假设所有产品都有相同成本。

例如第一秒返回成交101、102、103，下一秒返回102、103、104：完整响应会再写一次102、103。可比较保存第一批后，只追加104及下一次轮询的时间、成功状态、范围、条数和ID / 时间边界。同ID内容改变也保留，空响应和失败不能消失。这样保存已观察到的成交事实及轮询连续性，但不再承诺还原每张返回列表。仅按“ID大于历史最大值”过滤可能掩盖迟到或变化记录，不采用这种捷径。

P2已获授权评估这一窄范围表示变化：用有界最近窗口缓存原生ID和所保留字段，直接比较，不加逐笔SHA / 数据库查找，不扫描历史；重启后允许少量重复。若在相同输入下没有足够收益，就保留单份完整响应。版本和reader需能区分新表示；历史Raw和WS仍允许重复。轮询间成交超过返回窗口会有永久缺口，压缩存储不能解决采样本身的信息损失。

## 3. 规范化一条行情，附带许多摘要和重复来源信息

证据：[COMMON_FIELDS](../../../src/binance_market_data_recorder/normalize/model.py#L61)、[_candidate](../../../src/binance_market_data_recorder/normalize/pipeline.py#L280)、[_winner](../../../src/binance_market_data_recorder/normalize/pipeline.py#L464)。

每条规范化记录有来源chunk摘要、原payload摘要、语义身份摘要、内容摘要；即使只有一个来源，`duplicate_sources_json`也重复来源信息。现有字段有溯源、去重、冲突判断或公开格式用途，但“曾经设计过”不等于永久必要：P3沿实际消费路径检查，无用途的移除，自然ID / 直接字段比较足够时替换摘要，同步必要reader即可。

有一处可先保持格式优化：一个 Raw 响应解析成多条子记录时，`_candidate(record, parsed)` 会为每条子记录重新计算同一个完整 `raw_payload` 的 SHA-256。可以在该 Raw 记录的不可变边界内计算一次并复用。不能用不同记录间不受控的缓存替代验证。

保留能定位源chunk / ordinal的简单关系；大量重复来源描述只有实际消费者需要时才保留，不为删字段再建复杂关联平台。公开normalized格式有变更就明确版本和读取方式。Parquet对重复列可能已有压缩效果，不能按字符串长度推算磁盘收益。这些工作发生在离线规范化，不能算作当前WS接收循环的既定CPU根因。

## 4. 一次 normalize 命令仍从全体历史输入开始

证据：[load_source_chunks](../../../src/binance_market_data_recorder/normalize/raw.py#L103)遍历所有 manifest 并验证对应文件；[Normalizer._run_locked](../../../src/binance_market_data_recorder/normalize/pipeline.py#L734)再遍历源记录、生成临时 JSON、外部排序和去重后生成分区。内容寻址的输出复用并不意味着前面的全量输入工作已经免掉。

当前生产 service 没有默认调度 Normalizer；它由 [CLI](../../../src/binance_market_data_recorder/cli.py#L1363)按需运行。不能把这项按需成本说成“采集一直在全库重算”。但如果以后按小时在 VPS 上运行，历史越多，扫描和临时写入可能越多。

建议规范化跟着实际研究请求运行，有需要再限制日期 / 产品范围或仅处理新分区，必要时放在研究机器。首版稳定采集无需为了可能用到的全部派生格式持续生成第二套完整数据。此文不新增增量框架，也不取消新封存文件独立检查。

## 5. 每条 Raw 都重复携带版本、产品和连接信息

证据：[EventEnvelope](../../../src/binance_market_data_recorder/domain/event.py#L15)、[writer 的 canonical_mapping](../../../src/binance_market_data_recorder/spool/writer.py#L109)。每帧都有 schema、venue、market、symbol、stream、module、实例 / 版本 / 连接 ID 等，部分信息还同时出现在 chunk header；REST provenance 内的接收时间与外层 envelope 也重复。

这些信息帮助独立读取和定位来源，但“每帧重复编码”不是实现这些能力的唯一方法。若实测值得，可在未来格式中用块级稳定信息和明确的连接变更记录引用它们，保留实际时间、身份及顺序。压缩后重复字符串通常更便宜，格式变更却有 reader、断点恢复和归档兼容成本，因此不是当前必须重做 Raw v1 的理由。

小项包括将进程内固定的SDK包版本读取移到初始化，缓存单次请求的稳定元数据，减少逐条重复拼装。P3纳入这些重复流程的清理；块级格式仅在实测值得时推进。当前低频接口收益未测，不能夸成主瓶颈；来源信息仍须可恢复。

## 6. 压缩后摘要和解压后摘要可以共享一次独立回读

证据：[封存](../../../src/binance_market_data_recorder/spool/seal.py#L518)在压缩 / fsync 后解压读回核对内容；随后 [_manifest](../../../src/binance_market_data_recorder/spool/seal.py#L285)又完整读取压缩文件算 stored SHA-256。[validate_sealed_artifact](../../../src/binance_market_data_recorder/spool/seal.py#L649)同样先读压缩字节，再单独读并解压。

两种摘要分别标识压缩文件与解压内容，功能不同，均保留。可评估用同一受约束的读入流同时累计压缩字节摘要、解压内容摘要和统计，减少一次文件遍历；需要相同输入 / 输出及损坏回归，确认观察期间文件不会被替换或修改。此处只证明存在重复读取，尚未测出墙钟或 I/O 收益。

复制到归档目标后的独立完整回读、重试 / 重启重新验证、删除唯一源副本之前的身份核对发生在不同观察边界，不能随此优化删掉。文件名、inode、大小、mtime 也不能替代内容证明。没有修改现行归档协议或校验契约。

- ADR-0051 已取消每阶段重复全历史验收和私人审批链；历史审计命令仍存在，不代表新生产流程强制执行。

由这些资料和项目证据推导的实施顺序：P1继续修短通路的实际回归；P2落实单份表示、共享采集和源级资源配置，评估D06重叠；P3清理无用途哈希、合并同边界读取、让派生消费按需运行。保护独有且难补回的事实是本项目对未知用途的选择；不假装有一篇论文替我们决定K线、OI或清算的绝对价值。

不增加自动评分 / 动态丢包引擎、通用消息平台、全量历史迁移或新审批链。每项优化用相同工作量测CPU / RSS / I/O / 压缩字节与信息结果；源配置减少时另报信息覆盖变化，不与等价代码优化混为一谈。
