## Confirmed root causes

### USD-M session retirement was promoted to a core terminal failure

`UsdMCollector._run_capture_session()` owns streams, a snapshot task, and a
control task in an `asyncio.TaskGroup`. A disconnect, planned rotation, server
shutdown, outer resync, or global stop sets the session stop event. Before the
first snapshot completed, `_capture_snapshot()` interpreted that normal stop as
`SnapshotUnavailableError`. The TaskGroup propagated an `ExceptionGroup`, and
the Supervisor correctly converted the terminated core market task into
`CoreMarketTerminalFailure`. The first and last retained terminal tracebacks
show this exact call chain.

Spot already returned cleanly when its snapshot task lost the race to session
stop. The market-data continuity contract wasn't the cause: both collectors
keep a resync interval untrusted until a fresh snapshot and buffered diff bridge
succeed.

### sealed reconciliation ignored Archive ownership

Startup `reconcile_sealed()` scanned valid local Raw manifests, optionally
advanced `ACTIVE` or `RECOVERED` to `SEALING`, then unconditionally requested a
transition to `SEALED`. The independent Archive writer may already have
atomically moved the same chunk into `ARCHIVE_COPYING`, `ARCHIVE_VERIFYING`, or
`LOCAL_DELETE_PENDING`. Catalog correctly rejected those reverse transitions,
but the resulting `CatalogStateError` aborted Recorder startup and contributed
to the restart storm.

## Paths that passed

Archive completed 40,282 files (about 3.046 GiB). Archive evidence, internal
disk evidence, external disk evidence, and the registered target remained
healthy in all formal samples. The retained journals contain no USB reset or
disconnect, I/O, exFAT/filesystem, Catalog hash mismatch, or Raw hash mismatch
evidence.

## Independent risk: `recv_messages`

Project code doesn't access `recv_messages` or `ClientConnection` internals. It
uses the public `websockets.asyncio.client.connect()` and `recv()` APIs. The
traceback is entirely in `websockets==15.0.1`: `recv_messages` is initialized by
`connection_made()`, while `connection_lost()` assumes it already exists.
Calling those callbacks in the observed order reproduces the AttributeError in
a controlled offline fake. Upstream issue `python-websockets/websockets#1629`
records the same traceback and identifies an apparent asyncio protocol callback
ordering violation, but doesn't contain a deterministic real-transport
reproduction or fix. The 16.0 source retains the same access. M21.3 therefore
doesn't speculate with a dependency upgrade.

The next bounded investigation is a local HTTP CONNECT proxy that resets during
TLS promotion; it must not contact Binance or use production proxy settings.
