## 3. Root cause (confirmed independently from source) [DERIVED]

`src/binance_market_data_recorder/binance/usdm/websocket.py` (cf1e749):

- `_receive_connection()` returns `"planned_rotation"` on the rotation
  timeout and re-raises `(WebSocketException, OSError, TimeoutError)` on a
  disconnect.
- `_connection_loop()` catches the disconnect, logs it, backs off, and
  `continue`s with a **new `connection_id` but the same writer task and the
  same `_generation`**.
- Only `IngressBackpressureTimeout` produces gap evidence: boundary frame +
  `_record_gap_started` + generation++ + recovery marker.
- `seal_partial()` derives `complete` solely from Raw capture flags, so a
  cross-connection chunk with no flags seals as `gap=false/complete=true`.

The same structural gap exists in `binance/spot/websocket.py`
(`planned_rotation`, `server_shutdown`, `unexpected_disconnect` all continue
in one writer/generation) and in the depth-driven capture-session restarts:
`book_ticker`/`agg_trade`/`mark_price`/`liquidation` connections closed by a
session restart reopen in the next session with no boundary evidence.

## 7. Forward fix: unified Reconnect Boundary state machine [DERIVED]

Implemented in this PR (`fix/m21-4-reconnect-boundary-integrity`). Both Spot
and USD-M collectors route every transport boundary through one state
machine:

```
CONNECTED(generation N)
  -> boundary detected (ingress_backpressure / unexpected_disconnect /
     planned_rotation / server_shutdown / session_restart)
  -> DRAIN_OLD_GENERATION
  -> SEAL_OLD_GENERATION_INCOMPLETE
  -> CATALOG_GAP_STARTED_DURABLE (STREAM_DISCONTINUITY_STARTED)
  -> generation N + 1
  -> OPEN_NEW_CONNECTION
  -> FIRST_NEW_FRAME(sequence_gap)
  -> RAW_SYNC (StreamSpool.sync)
  -> CATALOG_GAP_COMPLETED (STREAM_DISCONTINUITY_COMPLETED)
  -> CONNECTED(generation N + 1, historical_continuity_restored=false)
```

Rules enforced by the implementation:

1. **No unpersisted last-old frame is ever mutated.** For unexpected
   disconnect / planned rotation / server shutdown / session restart there is
   no in-hand boundary frame; the sealed tail chunk gets the manifest-level
   `reconnect_gap` flag (never written into Raw frames, never a fabricated
   exchange payload). Evidence states `boundary_frame_persisted=false`,
   `boundary_kind=no_last_frame_available`, and records the disconnect
   transport time instead of a payload hash.
2. **The old generation is sealed before the new connection opens.** The
   writer drains, fsyncs, and seals (with `reconnect_gap` when required)
   before Catalog STARTED and before `generation += 1`.
3. **A connection that fails before delivering any frame extends the pending
   gap**: no second STARTED, no generation bump, no nested gap. The gap
   completes only after the first reliable new-generation Raw frame is
   persisted and synced.
4. **diff_depth never reconnects inside a capture session.** Any boundary
   retires the session; the outer loop restarts with a fresh connection,
   fresh REST Snapshot, and correct U/u/pu bridging before READY. Raw gap
   evidence is independent of orderbook recovery.
5. **Session restart (depth-resync-triggered) is a reconnect boundary for
   every stream** whose connection closes and reopens; a true global stop is
   not.
6. **`server_shutdown` and `sequence_gap` coexist**: the shutdown frame keeps
   its `server_shutdown` flag in Raw; the boundary additionally carries
   `reconnect_gap` at manifest level and a STARTED/COMPLETED pair.
7. **Crash recovery**: a unique unmatched STARTED (any reason) is restored
   with the same gap_id and generation; conflicting gaps fail closed.
8. **Writer/seal/sync/Catalog failures remain process-fatal** under the
   M21.4.2 owned-blocking-worker model; no new connection opens after a
   failed generation seal.

## 8. Manifest defense in depth [DERIVED]

`seal_partial()` now fails closed: a chunk containing more than one
connection_id with no `sequence_gap`, no `reconnect_gap`, and no
`blue_green_overlap` provenance is sealed with forced
`reconnect_gap` (`gap=true`, `complete=false`). Blue/green overlap remains
the only explicit safe multi-connection provenance and is preserved
unchanged. Legacy partials recovered at startup go through the same defense.

## 9. Historical remediation (design only; not executed) [DERIVED]

Historical sealed Raw/Manifest evidence is immutable and must not be
rewritten. Options to make the corrected judgment visible to consumers:

| Option | immutability | determinism | replay | normalization | consumer visibility | idempotence | auditability |
|---|---|---|---|---|---|---|---|
| A. Catalog additive integrity-correction events | preserved (new events only) | high | requires new replay queries | requires new normalization input | high (Catalog is the state plane) | yes (event_id keys) | high |
| B. Versioned superseding quality index (new artifact family) | preserved | high | additional artifact | additional artifact | high | yes | high |
| C. Replay-time reconnect-boundary inference | preserved | high (deterministic from connection_ids) | built-in | no Raw change | visible at replay time only | n/a | medium |
| D. No correction (keep historical claims) | preserved | n/a | n/a | n/a | misleading complete=true persists | n/a | low |

**Recommendation: A (+C as a replay-time safeguard).** The Catalog
operational-events table already carries the gap vocabulary; additive
`INTEGRITY_CORRECTION_STARTED/COMPLETED` style events (or a versioned
superseding index keyed by chunk_id) can mark the 4,680 unmarked intervals
without touching sealed artifacts. Any migration must be additive,
versioned, auditable, idempotent, and covered by tests before execution.

**POST_MERGE_MIGRATION_REQUIRED=true** (design documented; execution
explicitly deferred to a separately reviewed follow-up after this PR merges).
