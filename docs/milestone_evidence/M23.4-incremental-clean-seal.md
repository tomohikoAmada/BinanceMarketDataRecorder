## Trust boundary

For each append, `RawChunkWriter` first copies the caller's full Raw semantics
into one private immutable snapshot. `source_sequence` receives a private copy
behind a read-only mapping; flags are immutable. The exact canonical CBOR frame
and the statistics/connection-transition delta derive only from that snapshot.
After the complete exact frame write succeeds, and only then, the writer commits
the exact bytes to incremental SHA-256/verified byte count and commits semantic
statistics/transitions. Physical write progress is tracked separately.

Any partial/zero/exception write, evidence-commit failure, fsync failure, close
failure, observer/invariant failure after write, or closed-size mismatch poisons
the writer. A poisoned writer cannot issue clean evidence. A successfully
final-fsynced and closed writer can transfer its frozen memory-only evidence
exactly once through the writer-bound private clean-seal entry.

`seal_partial(path, ...)` has no evidence parameter and always calls
`scan_chunk(path)`. Recovery, crash leftovers, `RECOVERED`, poisoned, and
unknown partials retain full scan authority. The rare zero-record reconnect
marker also stays on `seal_partial()`.

Raw-v1 header eligibility now uses one `MAX_HEADER_BODY_BYTES = 64 * 1024`
authority. The encoder rejects a canonical header body above that exact bound
before any writer partial can be created; the decoder uses the same constant.
The bound and Raw-v1 wire layout are unchanged.

## Shared durable protocol and byte gate

Both scan-derived and live-writer-derived evidence enter one private shared
implementation for:

```text
ACTIVE / RECOVERED
  -> SEALING
  -> compress + fsync
  -> decompressed readback
  -> atomic sealed rename + directory fsync
  -> manifest
  -> SEALED
  -> source partial unlink + active-directory fsync
```

The compressor's actual consumed/stored counts are checked. Decompressed byte
count and SHA-256 must exactly match verified Raw evidence before rename. Stored
size/SHA, Zstd content size/checksum, atomic publication, manifest identity, and
Catalog ordering remain intact. A restart after Catalog `SEALED` but before
source unlink discovers the retained file only in `active/`. Recovery freshly
full-scans that retained Raw, then validates header/chunk identity,
uncompressed size/SHA-256, manifest, Catalog row, sealed artifact while its
same-host lifecycle still requires that source, and the exact archive
transaction/state. Only then does it unlink and fsync the redundant active
source. For ordinary `SEALED`, the sealed artifact is mandatory and receives
full stored and decompressed size/SHA-256 validation; missing or corrupt
authority preserves the retained Raw and fails startup recovery closed. If
ArchiveManager wins the post-`SEALED` race and advances through
`ARCHIVE_COPYING`, `ARCHIVE_VERIFYING`, `ARCHIVED_VERIFIED`,
`LOCAL_DELETE_PENDING`, or `LOCAL_DELETED`, cleanup preserves the winning
state and transaction and performs no Catalog transition. A clean but
nonmatching retained Raw fails closed and remains present.

## Validation matrix

The implementation includes deterministic tests for:

- exact incremental-versus-scan header/statistics/transition/size/SHA equality;
- 32 bounded seeded combinations covering zero/multiple records, payload sizes,
  optional exchange clocks, integer/string/mixed sequences, flags, connections,
  collector IDs, transitions, gaps, resync, overlap, and deployment IDs;
- controlled cross-thread caller mutation after snapshot but before write;
- `created_at_utc_ns` negative/zero/positive behavior, identity requirements,
  and both supported `max_frame_bytes` bounds;
- partial/zero/exception writes, complete physical write before evidence commit,
  evidence commit failure, periodic/final fsync, and close failure;
- header/frame-prefix/frame-body bit mutation, truncation, append-extra-bytes,
  incorrect compressor count, compression/readback/rename/manifest/Catalog
  failures, and Catalog `SEALED` before source unlink;
- clean-versus-scan manifest semantic equality;
- clean rotation scan spy, general `seal_partial()` scan spy, recovery seal scan
  spy, and zero-record marker scan spy;
- existing reconnect-boundary, M22.9, crash-recovery, and Raw golden suites.
- ordinary and oversized header encode/decode eligibility, including proof
  that an oversized header cannot create a clean writer;
- injected post-`SEALED` active-source unlink failure followed by deterministic
  Archive reservation and startup recovery at every reachable same-host
  successor state;
- reservation during retained-source validation, exact lifecycle/transaction
  preservation, repeated-startup idempotence, unchanged sealed/manifest/
  external bytes, and fail-closed rejection of a clean wrong Raw source.
- ordinary `SEALED` with a retained clean Raw and a missing, correct, or corrupt
  sealed artifact, including validation-before-unlink ordering and last-copy
  preservation.
